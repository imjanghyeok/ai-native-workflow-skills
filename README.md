```sh

```

**2. 과제 README가 있는 실제 작업 폴더의 터미널에서 제공 Codex를 실행합니다.** 실제 폴더는 과제 안내에서 확인합니다. `/home/user/exam-kit`은 참고 준비물이며 과제 작업 위치가 아닙니다. 이미 실행 중인 주작업 Codex가 있으면 이어 씁니다.

```sh

```

제공 메뉴/실제 설정에서 **허용된 Sol**을 선택하고 작업 위치를 확인합니다. 모델 ID를 추측한 실행 옵션을 붙이거나 제공 Codex를 업데이트하지 않습니다. 같은 제공 환경의 다중 세션 허용은 이미 확인한 안내를 따릅니다.

**3. 바로 아래 첫 `text` 블록 전체를 Sol에 한 번 붙여넣습니다.** clone 위치가 다르면 준비물 경로만 바꿉니다. 블록의 ‘실행 확인’은 본인이 확인한 사실을 전달하는 문장입니다. 모델/다중 세션을 확인하기 전에는 사실처럼 보내지 마세요. 모델 자신의 추측은 사용자 확인을 대신하지 않습니다.

**역할의 기본값:** Sol이 요구 해석·설계·공통 계약·중요 판단·통합을 맡습니다. Terra에는 Sol이 TODO·입출력/오류·권한/저장 규칙·수정 범위·정상/실패/경계 예상 결과를 정리한 구현을 넘깁니다. 모든 테스트 코드가 완성될 때까지 기다리는 방식은 아니며, Terra가 구현과 관련 테스트를 보완합니다. 계약 안의 구현은 자율 진행하고 새 정책/계약 변경은 Sol로 돌려줍니다. 이는 선택한 운영 전략이며 Terra의 속도/성능 우위를 보장하는 설명은 아닙니다.

**4. 이후에는 Sol이 실제 분석에서 만든 `docs/session-prompts.md`의 현재 안내를 따릅니다.** 기존 인계 문서를 사용하면 Sol이 안내한 경로를 엽니다. 준비물 README의 통합 블록을 Terra/리뷰에 다시 넣지 않습니다.

### 시간부터 확보하고 일감 배정

Sol이 화면/본인에게 확인된 **현재 시각·과제 남은 시간·전체 종료**에서 후속30분·대기/완료 여유와 검증·제출 예산을 먼저 뺍니다. 값을 모르면 한 번 확인하며 분석은 진행합니다. 새 Terra 일감은 전달/대기/구현뿐 아니라 합류·통합·수정 확인까지 남은 구현 예산에 들어올 때만 발급합니다. AI 응답시간을 고려한 위임/시간 안배도 평가에 포함된다는 안내를 반영했습니다.

예를 들어19:00 시작/과제180분이면 목표22:00, 새 기능 중단21:10~21:20, 핵심 검증/리뷰21:45~21:50까지, 이후 제출 준비를 권장합니다. **이는 준비 전략이며 시험 규정상 고정 마감은 아닙니다.** 늦게 시작하면 전체23:00에서 후속/대기/완료 여유를 확보하도록 목표를 앞당깁니다. [계산 기준과 재배정 방법](.agents/skills/task-triage/references/time-budget.md)을 따르며 선택 기능 축소·중요 실패 우선 검증·전체10GB 이하·저장 상태·본인 최종 완료 확인을 챙깁니다. 실제 제출 확정/후속 답변은 본인이 합니다.

### 이렇게 구성한 이유와 추가할 때의 기준

이 묶음은 **얇은 공통 경계 + 실제 과제에 필요한 스킬만 선택 + 분석 후 발급하는 일감**으로 구성했습니다. 폴더 생성과 중요한 요청/판단/실행 기록은 AI가 처리합니다. 언어는 기존 프로젝트를 우선하고 새 과제에만 익숙한 JS/TS를 기본 후보로 삼습니다. 프런트/백엔드는 독립 파일·계약으로 나눌 수 있을 때만 분담하며, UI는 필수 기능을 연결하고 여백·정렬·상태 표시를 정리하는 수준을 기본으로 합니다.

실제 코드에서 책임·API·데이터 흐름·권한·저장·의존성을 표/Mermaid와 파일·심볼에 연결하고, 제안/확정/거절과 이유·이점·한계를 기록합니다. 사용자에게 모든 세부 구현 승인을 요구하지 않으며, AI가 사용자 제안과 다른 근거·대안을 제시할 수 있게 했습니다. 공개 준비물에는 특정 시험 문제·데이터·답안을 넣지 않습니다.

추가 준비는 도구를 늘리기보다 **과제에 해당할 때만** 고릅니다. 외부 서비스가 있으면 환경변수·실패·재시도, 수정/저장이 있으면 새로고침·재실행 후 보존과 권한, 낯선 의존성이 있으면 버전·라이선스·대체 방법을 확인합니다. 시간 부족 시 필수 흐름/치명적 실패/실제 검증을 우선하도록 Sol에 남은 시간을 알려주세요. 이런 항목을 모든 과제의 의무 산출물로 늘리지는 않습니다.

### 데이터 → 수요/작업량 → 운영안 선택이 실제 요구라면

[전처리](.agents/skills/data-to-validated-dataset/SKILL.md) → [수요·작업량 분석](.agents/skills/demand-and-workload-analysis/SKILL.md) → [목표/제약·알고리즘·운영안 비교](.agents/skills/optimize-and-compare-plans/SKILL.md)를 필요한 범위에서 연결합니다. 원본/누락/중복·관측과수요·피크/동시용량을 구분하고 **실행 가능한 기준안, 필수 제약 검사, 동일 입력의 후보 비교**를 준비합니다. 예측/최적화가 없는 과제에는 추가하지 않습니다.

Sol이 해석·목표/제약·알고리즘 후보·TODO·독립 기대값을 정하고 Terra는 계약이 명확한 집계/처리/생성/API와 테스트를 구현합니다. 별도 리뷰는 누락수요·용량/일정 위반·평가기·기준안·최적성 주장과 실제 근거를 대조합니다. 목적점수만 좋고 필수 제약을 어기는 안은 추천하지 않습니다.

공개 후보는 [원문/커밋·라이선스·의존성·적용 기록](.agents/skills/task-triage/references/data-operations-sources.md)에 정리했습니다. K-Dense EDA의 필요한 절차만 MIT 고지를 보존해 재구성했고 Python 최적화/연구 스킬은 전체 설치하지 않았습니다. 추가 스킬은 패키지/MCP·외부AI 없이 기존 환경에서 적용하는 절차입니다.

```text
실제 과제 위치와 기존 README·AGENTS·코드 구조를 확인해 줘.
prepare-workspace.cjs를 실제 과제 위치에 실행해서 문서·데이터·도구·작업 로그 구조를 준비해 줘.
새 JS 과제라면 --starter js, 기존 프로젝트면 --starter none으로 시작해 줘.
충돌하는 기존 파일은 내용을 읽고 필요한 부분만 병합해 줘.
내가 탐색기에서 직접 파일을 만들거나 옮기게 하지 말고 필요한 파일 작업도 네가 처리해 줘.

각 요청의 원문을 로컬 worklog에 기록하고 requestId에
계획·선택·이유·대안·예상 결과·실제 결과·검증 근거·한계를 연결해 줘.
AI가 정리한 판단과 내가 직접 말한 생각을 actor로 구분해 줘.
기록 실패나 누락을 기록 완료라고 쓰지 말고, 실행하지 않은 사실은 만들지 마.
시험 자료와 로그를 git push·업로드·외부 전송하지 마.
```

생성 구조는 다음과 같습니다. 기존 프로젝트에서는 app/을 추가하지 않고 원래 코드 구조를 유지할 수 있습니다.

```text
실제과제/
  app/                         # 새 JS 과제일 때만
  docs/
    requirements.md
    design.md
    decisions.md
    verification.md
    WORKFLOW.md                # 생성된 기록 도구 사용법
  data/raw/
  data/processed/
  tools/worklog.cjs
  worklog/
    requests/                  # 요청 원문
    runs/                      # 요청/검증 실행별 입력·출력·종료 상태
    handoffs/
    events.jsonl               # 첫 기록 시 생성
```

‘사고과정 기록’은 **설명 가능한 선택·이유·대안·예상·근거·한계**로 구조화합니다. 본인이 남긴 생각은 actor=user, AI의 설명과 판단은 actor=ai로 구분합니다. AI가 사용자의 판단을 추측해 채우지 않습니다. 문서 템플릿이 생겼다는 사실만으로 실제 분석·구현·검증이 완료된 것은 아닙니다.

### 요청 원문을 먼저 저장하고 싶다면

일반 Codex 대화에서는 AI가 요청을 전사해 기록합니다. 이 방식은 모든 입력을 독립적으로 자동 포착하는 기능은 아닙니다. **제공 CLI가 exec/resume/--json을 지원하고 실제 환경에서 사용 가능할 때만**, 생성된 과제 폴더에서 다음 단일 세션 기록기를 사용할 수 있습니다.

```sh
node tools/worklog.cjs chat
```

요청을 여러 줄 입력한 뒤 `/send`를 입력하면 **원문 저장 → 현재 제공 Codex 실행 → 공개 메시지/도구 이벤트·종료 상태 저장** 순서로 진행합니다. 다음 요청은 같은 세션 ID로 이어가며 `/exit`로 끝냅니다. 기록기는 요청 ID와 판단 요약 작성 안내도 함께 전달합니다. 원문 파일과 실제 전달 입력은 별도로 보관하므로 안내가 덧붙었다는 사실을 확인할 수 있습니다.

모델을 자동 대체하거나 글로벌 계정·MCP·Codex 버전을 바꾸지 않습니다. 권한은 기본 CLI 설정을 따릅니다. 허용된 쓰기가 필요한 지원 환경에서는 `--workspace-write`를 명시할 수 있지만 관리 정책을 우회하지 않습니다. CLI 기능이 없거나 승인 입력이 필요하면 일반 제공 Codex와 AI 기록 방식으로 돌아갑니다. 하네스 밖 TUI·다른 세션·브라우저 입력은 수집하지 않습니다. reasoning 항목은 제외하며 설명 가능한 판단은 별도 note로 남깁니다.

기록기는 모델을 자동 대체하지 않습니다. **현재 제공 CLI에서 실제 응답이 확인된 허용 모델 ID**를 알고 있다면 `ask/chat --model 실제ID`로 그 실행에만 전달할 수 있습니다. 글로벌 모델/계정 설정은 바꾸지 않습니다. 모델 옵션을 생략하면 CLI 기본값을 사용하므로, 권장 모델만 사용하려는 경우 기본값이 다른 모델이면 그대로 진행하지 마세요. 표시명으로 ID를 추측하거나 오류를 다른 모델로 자동 우회하지 않습니다. `node tools/worklog.cjs --help`로 명령도 확인할 수 있습니다.

예상·실제 결과와 실행 명령을 같은 requestId로 연결하는 note/run 명령은 생성된 `docs/WORKFLOW.md`에 있습니다. 로그는 작업 공간 안에만 두고 공식 플랫폼 기록을 대체한다고 주장하지 않습니다. 기록기는 방화벽/격리 샌드박스가 아니며 시험 제한은 계속 적용됩니다.

문제 이름이 아니라 입력·요구 결과로 고릅니다. 아래 예는 출제 예측이 아닙니다.

## 시험 환경에서 clone해서 사용하기

사용자가 전달한 최신 운영 메일은 공개 저장소의 지침·Skill·하네스·템플릿·코드를 상세 가이드의 허용 범위에서 활용할 수 있다고 안내합니다. 비공개 자료·외부 전송·결과물 전체 대체까지 허용하는 뜻은 아닙니다. 사용하는 저장소는 결과 통지 전까지 공개 상태를 유지하며 실제 최신 운영 안내와 제공 도구 제한을 따릅니다.

### 1. 응시 화면 안에서 가져오기

개인 PC 파일 업로드 대신, 허용된 경우 **응시 환경의 터미널과 제공 AI**로 가져옵니다.

```sh
git clone --depth 1 -- https://github.com/imjanghyeok/ai-native-workflow-skills.git /home/user/exam-kit
git -C /home/user/exam-kit rev-parse HEAD
ls -a /home/user/exam-kit/.agents/skills
```

`/home/user/exam-kit`은 가져온 스킬을 두는 예시 위치이며 과제 폴더와 구분합니다. 이미 그 폴더가 있다면 내용을 확인하고 다른 빈 경로를 사용하세요. 기존 과제·설정·파일을 삭제하거나 덮어쓰지 않습니다. 가져온 커밋 ID를 남겨 어떤 준비물을 사용했는지 확인할 수 있게 합니다.

제공 AI에게 요청할 예:

```text
공개 저장소 https://github.com/imjanghyeok/ai-native-workflow-skills.git 를
/home/user/exam-kit 에 clone해 줘. 폴더가 이미 있으면 덮어쓰지 말고 상태를 알려줘.
가져온 README와 스킬 목록을 확인하고 커밋 ID를 알려줘.
과제 파일·AGENTS.md·Codex 설정 전체는 변경하지 마.
```

### 2. 단계별 복사 프롬프트 (설치 없이 사용)

clone을 마친 뒤 **실제 과제 폴더에서** 제공 Codex를 실행합니다. 터미널에서 실행하는 환경이라면 명령은 `codex`입니다. 이미 Codex가 실행 중이면 그 대화에서 이어가세요.

아래 코드 블록을 **한 단계씩 복사**하고, 결과를 읽은 뒤 다음 단계로 진행하세요. `/home/user/exam-kit`을 다른 위치로 바꿨다면 프롬프트의 경로도 바꿉니다. 자동 스킬 설치나 MCP 연결 없이, 스킬 파일을 읽어 절차를 적용하는 방식입니다. 상대 경로로 연결한 `references/` 문서는 해당 스킬 폴더를 기준으로 읽습니다.

#### 단계 1 · README와 현재 프로젝트 분석

```text
/home/user/exam-kit/.agents/skills/readme-to-requirements/SKILL.md를 읽고 적용해 줘.
먼저 현재 작업 경로와 실제 과제 폴더를 확인해 줘.
/home/user/exam-kit은 참고 스킬 폴더이며 과제 폴더와 구분해 줘.
과제 폴더를 확정할 근거가 없으면 경로를 추측하지 말고 나에게 확인해 줘.

적용되는 AGENTS.md, 과제 README·안내, 기존 코드·데이터·테스트·실행 설정을 읽어 줘.
다음 내용을 출처 파일·위치와 함께 정리해 줘.
1. 해결할 문제와 사용자가 끝낼 수 있어야 하는 업무
2. 필수 기능·제약·제출 파일·실행 방법
3. 현재 구현된 부분과 부족한 부분
4. 확인된 사실, 가정, 모호하거나 충돌하는 사항

제공 자료의 예시를 이번 과제의 필수 요구사항으로 단정하지 마.
이번 단계는 분석만 하고 제품 코드는 수정하지 마.
```

#### 데이터가 있는 경우 · 단계 1 뒤에 탐색만 수행

CSV·JSON·로그·스프레드시트·PDF 등 제공 자료가 업무 입력일 때만 적용합니다. 이 요청은 구조와 품질을 조사하는 단계이며 가공 실행 단계와 구분합니다.

```text
/home/user/exam-kit/.agents/skills/data-to-validated-dataset/SKILL.md를 읽고 적용해 줘.
이번에는 데이터 탐색과 규칙 정리만 해 줘. 원본을 바꾸거나 가공 코드를 구현하지 마.
가공 결과 파일 생성·패키지 설치·설정 변경도 아직 하지 마.

과제에 필요한 제공 자료부터 파일·시트·형식·규모와 작은 표본을 확인해 줘.
한 행/항목의 의미, 필드·타입·단위·날짜/시간대·키 후보와 출처 위치를 정리해 줘.
원본값과 정규화값, ID 선행 0, 0/null/빈 값, 비율과 퍼센트를 구분해 줘.
중복·상충 ID·잘못된 값·누락·파싱 실패 가능성을 확인하고,
여러 자료를 연결한다면 키 관계·미매칭·행 증식 위험을 짚어 줘.
```
