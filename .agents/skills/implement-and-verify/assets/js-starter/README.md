# 외부 패키지 없는 JavaScript 시작본

Node.js 18 이상을 전제로 하는 **입력→업무 함수→CLI/API→웹 화면 연결 예제**다. 실제 과제의 완성 답안이 아니다. 현재 업무 함수는 records 배열의 개수만 센다. TypeScript 컴파일러·MCP·외부 모델·API 키·npm install이 필요하지 않다. 기존 과제가 있으면 이 시작본으로 교체하지 않는다.

## 실행

이 폴더를 실제 과제에서 사용할 **새 빈 폴더**에 복사하거나 필요한 파일만 병합한다. 실제 과제 README·지침이 우선이며 기존 파일은 덮어쓰지 않는다. 과제에서 불필요한 예제 파일은 복사하지 않아도 된다.

```sh
node --version
node cli.cjs input.example.json
node --test test.cjs
node server.cjs
```

CLI 예제 결과는 `{"recordCount":2}`다. 잘못된 JSON·없는 입력·스키마 오류는 종료 2와 stderr이며 stdout 성공 결과는 없다. 서버는 기본 3000 포트와 0.0.0.0으로 실행한다. 미리보기에는 **실제 포트와 /**를 입력한다. 서버 터미널은 유지한다. 포트가 사용 중이면 허용된 다른 포트로 `PORT=3001 node server.cjs`처럼 실행한다. 동작 중인 감독 연결이나 다른 서버를 일괄 종료하지 않는다.

`POST /api/analyze`는 application/json의 `{records:[객체,...]}`를 받고 `{recordCount:숫자}`를 반환한다. 요청 한도는 64 KiB이며 400/405/413/415 오류를 구분한다. `/health`는 상태 확인용이며 업무 검증을 대신하지 않는다. 저장·인증·DB·파일 업로드는 구현하지 않았다. 필요한 경우 실제 과제 계약에 맞춰 추가한다.

## AI에게 수정시킬 위치

- core.cjs: 실제 업무 입력 검증·계산·처리 규칙. CLI와 API가 함께 사용한다.
- cli.cjs: 파일 입력/표준 출력·오류 코드.
- server.cjs: API 계약·정적 파일·요청 오류.
- index.html/style.css/app.js: 실제 화면·입력·상태·결과 표시.
- test.cjs: 예제 검증이므로 실제 요구의 기대값과 실패 사례로 보완.

입력/응답 형식이 과제와 다르면 호출부·화면·테스트도 함께 맞춘다. TypeScript가 이미 설정된 프로젝트라면 그 설정을 유지한다. TS를 선호한다는 이유만으로 기존 JS 시작본에 실행 확인 없는 .ts 확장자만 붙이지 않는다.

## 검증 한계

Node 22.14.0에서 CLI·핵심 처리·HTTP/정적 파일 테스트를 실행했다. Node 18의 모든 세부 버전·실제 시험 환경은 별도 확인이 필요하다. 자동 브라우저 조작은 포함하지 않는다. 웹 화면 입력→버튼→결과는 허용된 수동 미리보기로 직접 확인해야 하며 HTTP 성공만으로 화면 검증 완료라고 쓰면 안 된다.
