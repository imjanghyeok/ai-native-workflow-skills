# 작은 웹 도구를 끝까지 완성하기

웹 과제에만 적용한다. 기존 프레임워크·실행 명령·포트·파일 구조를 먼저 따른다. 화면 장식보다 원문 필수 업무 흐름을 먼저 연결한다.

## 상태와 업무 흐름

입력/선택 → 검증 → 처리 → 결과 확인 → 저장/내보내기 중 실제 요구 범위를 끝까지 구현한다. 입력 오류·로딩·빈 결과·성공·실패를 구분한다. 요청이 실패하거나 저장이 끝나지 않았는데 성공 표시를 하지 않는다. 중복 클릭·늦은 응답이 최신 결과를 덮는 문제는 실제 과제에 관련될 때 확인한다.

필터와 페이지·선택·수정 상태의 관계를 명시한다. 새로고침 후 보존이 요구되면 실제 저장 경로를 검증한다. 파일 입력·다운로드도 응시 환경에서 허용된 기능으로 확인하며 개인 PC 업로드 제한을 우회하는 도구를 추가하지 않는다.

## 화면 확인

레이블·키보드 조작·읽기 순서, 긴 한글/숫자/파일명, 표와 버튼의 넘침, 좁은 화면에서의 배치를 필요한 만큼 확인한다. 컨테이너를 보기 좋게 만든 것과 업무가 실제 완료되는 것은 별도다. 백엔드 오류/입력 0건/유효하지 않은 값도 화면에서 분명히 보이게 한다.

## 실행 근거

실제 서버 포트·경로·바인딩을 확인한다. 환경이 0.0.0.0을 요구하면 그에 맞추고 서버 프로세스를 유지한다. HTTP 응답·단위 테스트·빌드 성공만으로 브라우저 사용 흐름을 확인했다고 쓰지 않는다. 허용된 수동 미리보기로 실제 입력→결과→저장/내보내기를 확인하고, 사용자의 확인이 필요하면 구체적인 입력과 기대 결과를 안내한다. 시험에서 금지된 Computer Use는 사용하지 않는다. 브라우저를 확인할 수 없으면 해당 UI 검증은 미확인으로 남긴다.
