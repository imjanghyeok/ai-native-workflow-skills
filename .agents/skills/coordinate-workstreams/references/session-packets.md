# 분석에서 세션별 복사 지시 만들기

일감은 원문 분석·최소 설계·전역 컨벤션과 실제 파일 경계를 확인한 뒤 정한다. 모델별로 프런트/백엔드를 미리 고정하거나 과제 내용을 공개 준비물에 채우지 않는다. 작은 과제는 주작업 하나와 리뷰 단계로 충분하다.

## 만들 결과

기존 계획/보드에 합칠 수 있다. 여러 세션에 실제로 전달할 때만 `docs/session-prompts.md` 또는 기존 인계 문서에 **복사 가능한 완성 블록**을 만든다. 내용은 실제 과제 공간에만 저장한다. 사용자가 직접 채워야 할 `[경로]`·`[일감]` 같은 빈칸을 남겨 실행 준비가 된 것처럼 쓰지 않는다.

주작업 계속 지시도 포함해 각 복사 지시는 독립된 `text` 코드 블록 하나로 작성한다. 사용자 안내·전달 상태·실행 명령 설명은 블록 밖에 두어 본문만 복사할 수 있게 한다. 다른 세션의 문맥이 없어도 찾을 수 있도록 읽을 문서/스킬의 경로를 절대 경로나 명시한 작업 폴더 기준으로 완전히 적고 중간 경로를 생략하지 않는다.

각 블록에 다음을 실제 값으로 연결한다.

- 대상: 주작업 계속 / Terra 일감별 / 별도 리뷰. 일감 ID·배정 대상·현재 상태·발급 시점/계약 버전.
- 실제 작업 폴더와 먼저 읽을 원문·요구/설계·컨벤션·필요한 스킬의 경로. 다른 세션이 이전 대화를 알고 있다고 가정하지 않는다.
- 목표·R-ID·선행 조건·입출력/실패 계약·쓰기 소유 범위·공통 파일 담당.
- 관찰 가능한 완료 기준·실제 지원되는 검증 명령/입력과 한계. 세부 함수·모든 행동은 미리 지정하지 않는다.
- 충돌·계약 변경·필수 정책 미정 시 누구에게 무엇을 인계할지. 기술적 재량과 사용자 판단을 구분한다.
- 고유 인계 파일/실행 출력 경로, 직접 실행과 다른 담당 결과의 출처 구분. 공유 보드/로그는 통합 담당만 쓴다.
- 실제 시험 경계: 제공 모델/환경만 사용, 모델 ID 추측/대체·업데이트·새 MCP/외부 AI·외부 전송/push·감독 변경 금지. 원본/타 담당 파일 보존.

제공 CLI가 실제 확인됐을 때만 새 터미널의 작업 경로/실행 방법도 안내한다. 플랫폼 사용 방식이나 모델 선택 메뉴를 발명하지 않는다. 사용자는 제공 선택지에서 해당 허용 모델을 확인하고 완성 블록을 붙여넣는다. 이 문서가 새 세션/다른 채팅으로 자동 전송할 권한을 추가하지 않는다.

## Terra 전달 준비 기준

Sol이 판단 부담을 줄인 뒤 발급한다. 요구 ID별 TODO, 기존 파일/계약과 수정 소유 범위, 입출력·오류·권한·저장 규칙, 정상/실패/경계 사례의 입력·예상 결과·실행 방법을 카드에 연결한다. 검증 기준이 모호한 상태를 구현 담당에게 떠넘기지 않는다. 모든 테스트 코드의 선완성은 필요 없고 Terra가 구현에 맞는 테스트를 추가한다. 미정 정책에 의존하는 부분은 발급하지 않는다.

Terra는 계약 안에서 방법을 선택하되, 계약 변경/새 업무 판단/범위 확장이 필요하면 현상·근거·영향·대안을 Sol에 인계한다. 무조건 대기하지 말고 영향 없는 TODO는 진행한다. Sol은 원문 요구 안의 기술적 판단은 처리하고 실제 사용자 판단만 올린다. 리뷰는 별도 세션에서 수행하며 복잡한 원인 분석·리뷰 수용/통합 판단은 Sol이 맡는다.

## 남은 시간과 합류 조건

[남은 시간 예산](../../task-triage/references/time-budget.md)에 따라 Sol은 실제 타이머/출처와 검증·제출·후속 예약을 먼저 확인한다. 카드에 기준 시각/남은 예산·합류 목표·마감 시 범위 축소/인계할 현재 파일·실행 결과·실패·남은TODO를 연결한다. 전달·대기·통합·수정 확인까지 감당 가능한 독립 일감만 발급하고, 검증/제출 구간을 침범할 새 기능 카드는 만들지 않는다. 이미 실행 중인 담당의 파일 소유를 확인해 조정하며 동시에 덮어쓰지 않는다. 타이머를 실제로 볼 수 없으면 추정으로 표시한다.

웹 구현/검증 카드에는 제공 Browser 미리보기·실제포트/경로·서버유지와 외부 창 자동 열기 금지를 연결한다. 워커는 자기 프로젝트 실행 경로만 조정하고 포커스/감독/플랫폼 설정을 바꾸지 않는다. 리뷰는 기능별 실제 코드책임·사용 순서·검증근거/주체와 UI미확인을 대조하며 제품 변경은 담당 소유자에게 인계한다.

## 발급 시점과 상태

1. 분석 결과에서 사용자 판단/현업 질문/AI 재량/직접 확인 항목을 분리한다. 미정 정책에 의존하지 않는 일감만 `전달 가능`으로 발급한다. 준비가 안 된 일감은 이유·필요 조건만 적고 실행용 블록으로 내보내지 않는다.
2. Terra 일감을 발급하면서 Sol 자신이 계속할 독립 작업과 수정하지 않을 파일도 함께 정한다. 카드 생성은 전달/착수가 아니다. 실제 전달 확인이나 담당 인계가 오기 전에는 `준비` 상태로 둔다. 여러 워커가 같은 카드를 자동 선점하지 않게 한다.
3. 계약/쓰기 범위가 바뀌면 영향받는 담당과 버전을 맞추고 카드를 다시 발급한다. 이미 시작한 일감은 변경 전달/수신 상태를 구분하고, 옛 카드를 그대로 실행하지 않게 알린다.
4. 완료 보고를 받은 뒤 코드 상태를 식별하고 리뷰 카드를 발급한다. 미완료 다른 일감과 독립된 범위를 리뷰할 수는 있지만 그 범위/기준을 명시한다. 제품 코드 수정 금지, 별도 리뷰 보고 경로, 임시 검증 쓰기 범위와 원문/실행 근거를 포함한다.
5. 리뷰 결과를 주작업에서 원문·재현과 대조해 채택/수정 채택/거절/보류한다. 수정 카드는 담당 소유자에게, 재리뷰 카드는 새 기준 상태에 맞춰 갱신한다. 리뷰어에게 자기 지적을 바로 제품 코드에 고치게 하지 않는다.

이미 전달한 본문은 발급 ID별로 보존하고 현재 상태는 블록 밖에서 갱신한다. 지시가 달라지면 새 버전을 발급한다. 현재 전달할 지시와 완료된 역사 블록을 구분해 재실행을 막는다.

## 사용자에게 보여줄 지금 할 일

카드 문서 상단과 인계 메시지에 아래 항목을 짧게 모은다. 사용자 자신의 결정과 업무담당자에게 받아야 할 답변은 구분하고, 직접 확인은 입력/기대 결과/근거와 사용자 확인 여부를 명시한다. 다른 문서에 흩어 놓고 사용자가 다시 조합하게 하지 않는다.

| 구분 | 분석/실제 진행에서 뽑을 내용 |
| --- | --- |
| 지금 판단 | 질문·근거 R-ID·선택지/장단점·추천/이유·답 전 진행 범위. 없으면 없음 |
| 현업/Helper 확인 | 업무 정책/플랫폼 절차를 분리한 질문 초안. 실제 답변 전 미확정 |
| 지금 전달 | 복사할 블록 제목·대상 세션·해당 일감·다른 세션과 겹치지 않는 범위 |
| 지금 직접 확인 | 실제 입력/행동·기대 결과·근거 위치·미확인. AI의 실행 여부와 사용자의 확인 여부를 구분 |
| 다음 확인 시점 | 일감 완료/중요 계약 변경/리뷰 완료 등 조건. 고정된 승인 횟수나 시간 대기를 만들지 않음 |

첫 분석 때 모든 후속 결정을 예측하지 않는다. 새 정보/구현/실행/리뷰가 생길 때 위 목록을 짧게 갱신한다. 단순 스타일·문구·되돌릴 수 있는 구현 선택은 AI가 진행한다. 제출 전에는 실제 완료/미완료·검증·주요 코드 흐름·선택의 이점/한계를 사용자가 확인할 항목으로 정리한다. 실제 제출 확정과 AI 사용 금지 후속 답변은 본인이 한다.
