기존 계획 문서에 합쳐도 된다. 넓은 과제에만 `docs/work-board.md`로 분리한다. 통합 담당 한 명만 공유 보드를 수정한다. 일감 수/세션 수를 고정하지 않는다.

상태는 `준비/진행/막힘/리뷰 대기/수정 필요/검증 완료` 정도로 충분하다. 실제 세션이 없으면 `미배정`이라고 쓴다. 담당과 실행 여부를 지어내지 않는다.

## 계약·전역 컨벤션

루트 설정·의존성·잠금 파일·공유 타입·API 계약·공통 문서의 쓰기 소유자를 정한다. 원문 계약이 우선이며, 중요한 변경은 변경 이유·영향받는 일감·검증을 알리고 버전을 맞춘다. 작업 시작 전에 모든 상세 설계를 끝낼 필요는 없다.

프런트/백엔드 분담 시 최소 계약은 실제 요구에 필요한 요청/응답/오류, ID·null·단위, 인증 주체 전달/서버 검사 위치, 저장 성공 의미다. 역할·인증·저장이 없는 과제에 새 기능을 만들지 않는다.

일감 프롬프트는 다음 정보로 충분하다:

```text
일감 ID: [실제 ID]
목표·원문 요구: [관련 R-ID와 파일]
읽을 계약·전역 컨벤션: [경로/버전]
쓰기 범위: [소유 파일/디렉터리]; 공통 파일 소유자: [통합 담당]
선행 조건·입출력·오류 계약: [확정/미정 구분]
완료 기준·실제 검증: [관찰 가능한 결과]
범위 안 구현 방법은 판단해서 진행하고, 계약/다른 소유 파일 변경은 먼저 제안해 줘.
작업 결과·실제 명령/출력·한계·리뷰 요청을 지정된 일감별 인계 파일에 남겨 줘.
```

이것은 빈 양식이다. 과제별 내용은 시험 작업 공간에서만 채운다.
