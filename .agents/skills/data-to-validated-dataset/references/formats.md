# 형식별 탐색·추출 확인 사항

이 표는 도구 선택과 점검 가이드다. 모든 형식에 대한 추출 코드나 실제 연결 도구를 제공하는 것은 아니다. 현재 환경의 기존 파서·라이브러리·허용 도구부터 확인한다.

| 형식 | 먼저 확인할 것 | 조용히 틀릴 수 있는 지점 |
| --- | --- | --- |
| CSV/TSV | 인코딩·BOM, 구분자, 인용부호, 헤더 중복/누락, 필드 내부 줄바꿈, 행 의미 | 단순 쉼표 split, 선행 0 소실, 잘못된 행 자동 생략, 물리적 줄과 논리적 레코드 번호 혼동 |
| JSON/JSONL | 최상위 객체/배열, 중첩 경로, JSONL의 행별 객체, 키/타입/배열 크기 | 배열 펼침으로 원본 수량 반복, null/키 누락/빈 값 혼동, 앞부분만 읽고 전체 스키마로 단정 |
| 로그 | 이벤트 경계, 여러 줄 이벤트, 타임스탬프·시간대, 설비/사건 ID, 순서 | 줄 수를 사건 수로 간주, 다른 설비의 같은 코드 병합, 정규식 미매칭 줄의 묵시적 누락 |
| 스프레드시트 | 시트·헤더 위치, 병합 셀, 날짜 표시/저장값, 수식/계산값, 숨김·합계 행 | 합계 행 재집계, 표시 문자열을 실제 값으로 간주, 오래된 수식 캐시를 최신값으로 단정 |
| PDF/문서 | 텍스트/스캔 여부, 쪽·표·제목 구조, 다단 편집, 표의 단위·주석 | 읽기 순서/열 정렬 깨짐, 반복 머리글, OCR 숫자 오인, 빈 추출을 자료 없음으로 단정 |
| 제공 HTML | 실제 표/문서 구조, 표 제목·단위·반복 헤더 | 화면 장식·스크립트 텍스트까지 자료로 혼합, 없는 열을 위치만으로 추정 |

CSV의 ‘같은 열 이름이 반복된 헤더’와 ‘본문에 헤더 내용이 한 행으로 다시 나타남’은 다른 경우다. 원문에서 각각의 처리가 정해져 있는지 확인하고 리뷰 제안을 이유로 정책을 임의로 같게 만들지 않는다.

## 숫자는 파싱 성공과 정확성을 따로 확인

입력/합계의 단위·범위·허용 정밀도를 확인한다. JavaScript Number의 안전 정수 범위를 넘는 값을 조용히 반올림해 채택하지 않는다. 개별 입력은 범위 안이어도 합계가 넘을 수 있으며, JSON 직렬화·재읽기 단계에서도 손실이 생길 수 있다. 실제 요구에 따라 정확한 정수 표현·출력 방식·범위 확인을 선택하고 필요한 경계를 검증한다. 원문이 허용한 값을 편의를 위해 invalid로 제외하거나 필수 출력 타입을 바꾸지 않는다. 근거 없이 ‘정밀도 한계’만 적어 놓고 정확한 집계 요구를 충족했다고 보고하지 않는다. 비율의 부동소수 표현과 정수 수량 보존은 별도 문제로 다룬다.

## 원본과 추출값 연결

- 표 데이터는 파일·시트·레코드 ID·원본 행을 가능한 수준으로 유지한다. 필드 내 줄바꿈이 있으면 행 번호가 물리적 줄인지 논리 레코드인지 명시한다.
- JSON은 파일·객체 키/경로·배열 위치, 로그는 파일·원본 위치·사건 ID, 문서는 파일·쪽·표/절 등으로 연결한다.
- OCR 또는 레이아웃 추출 결과는 원본 이미지/문서와 실제 대조한다. 도구가 없으면 추출/대조 불가를 기록하며 수치를 추측하지 않는다.
- 원본이 외부 URL이면 실제 환경에서 접근이 허용된 경로만 사용한다. 웹 스크래핑이나 별도 API 연결이 과제의 필수라고 추론하지 않는다.
