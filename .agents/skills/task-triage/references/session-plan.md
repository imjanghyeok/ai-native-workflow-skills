# 여러 제공 세션의 일감 분담

실제 사용자가 같은 제공 환경에서 여러 Codex 동시 사용을 허용받았다고 확인하면 그 정보를 따른다. 이 확인을 다른 계정·외부 AI·새 플랫폼 접속 권한으로 확대하지 않는다. 단순 터미널 탭 지원만 알고 있다면 Codex 동시 사용 허용은 별도로 확인한다. 세션 수·실제 모델·자원 제한은 현재 환경 기준이다.

## 작은 구성부터

통합 담당 + 필요한 워커 + 읽기 전용 리뷰로 시작할 수 있다. 모든 과제에 프런트/백엔드/리뷰 3개 세션을 고정하지 않는다. 역할을 Sol/Terra에 영구 고정하지 않고 실제 제공 선택과 작업 특성으로 고른다. 과제·계약이 작으면 같은 세션으로 끝낸다.

| 역할 | 쓰기 범위·완료 책임 |
| --- | --- |
| 통합/주작업 | 원문·공통 계약·전역 컨벤션·루트 설정/잠금·공유 보드/로그·통합 검증 |
| 프런트 (필요할 때) | 합의한 화면/상태/요청 계약과 지정 UI 파일; 별도 시각 디자인은 기본 범위 아님 |
| 백엔드 (필요할 때) | 지정 API/업무/저장 파일; 공통 스키마·설정을 임의 변경하지 않음 |
| 데이터/분석 (필요할 때) | 지정 원본을 읽고 별도 가공/계약 근거; 원본 불변 |
| 리뷰 | 동결 기준 코드 읽기, 격리된 출력 검증, 지적·근거·인계; 제품 코드 직접 수정 금지 |

일감 배정은 [coordinate-workstreams](../../coordinate-workstreams/SKILL.md)와 [SESSION-HANDOFF](../../../../templates/SESSION-HANDOFF.md)를 필요한 만큼 사용한다. 구체적인 내부 구현은 맡기되 목표·쓰기 소유·입출력/실패 계약·완료 기준은 명확히 한다. API 계약이 미정이면 서로 다른 구현 대신 계약 조사 등 독립 작업부터 나눈다.

공통 문서·worklog 공유 이벤트는 통합 담당 한 명만 쓴다. 워커는 일감/세션별 인계 파일과 고유 실행 출력 경로를 쓴다. 기록기가 동시 append의 완전성/순서를 보장한다고 가정하지 않는다. 사용자의 판단을 AI가 추측해 채우지 않는다.

작업 전달은 실제 지원 기능이나 같은 환경 터미널에서 사용자가 복사하는 일감 프롬프트로 한다. 전송하지 않은 일을 배정했다고 표시하지 않는다. 네이티브 기능이 없는데 자동 API/Task/서브에이전트를 발명하지 않는다. 이 묶음은 별도 런처·다중 계정·자동 승인 루프를 추가하지 않는다.

리뷰 대상 상태를 식별하고 변경 중이면 freeze 또는 영향 범위만 재검토한다. 별도 세션 검토와 같은 세션의 역할 전환을 구분한다. 지적은 원문·재현과 대조해 채택/수정 채택/거절/보류를 기록한다. 리소스/대기 비용이 이득보다 크면 세션을 줄이고 필수 흐름을 우선한다.
