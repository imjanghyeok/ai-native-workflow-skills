# 필요한 웹 기능을 끝까지 연결하기

기존 스택·원문 요구를 우선한다. 프런트는 단정한 배치·읽을 수 있는 표/폼·명확한 상태로 업무를 완료하게 한다. 별도 시각 디자인, 애니메이션, 이미지 생성, 디자인 시스템·UI 프레임워크 도입을 기본 일감으로 만들지 않는다. 사용자가 시각 작업을 요청하면 그 범위를 따른다.

UI/UX 기본 수준은 `필수 기능 연결 → 실제 사용 흐름 확인 → 가볍게 스타일 정리`다. 바이브 코딩으로 기존 컴포넌트/기본 CSS의 여백·정렬·색·버튼을 일관되게 맞추고, 어긋난 박스·잘리는 표·헷갈리는 조작을 고친다. 스타일과 기본 오류 문구는 합의된 범위의 AI 재량으로 진행하고, 업무 흐름·기능 의미·중요한 접근성/권한 계약이 바뀔 때만 판단 사항으로 올린다. 별도 시안이나 과한 효과보다 필요한 동작을 우선한다.

## 나누기 전에 계약

화면 행동 ↔ 실제 endpoint/입출력/오류 ↔ 업무 처리 ↔ 저장 책임을 맞춘다. 여러 세션이 허용되고 경계가 독립적이면 프런트/백엔드 파일 소유를 나눈다. 루트 설정·공유 타입·API 계약·잠금 파일은 통합 담당 소유다. 코드 분리는 배포 프로세스 분리와 다르며 프런트/백엔드 분담을 위해 두 서버를 강제하지 않는다.

## 기능 중심 프런트

- 필수 조회/입력/수정/결과 회수 중 실제 요구만 만든다. 탐색·입력 라벨·키보드 조작·오류 위치가 명확한 네이티브 요소와 기존 컴포넌트부터 사용한다.
- 로딩/빈 결과/잘못된 입력/권한 없음/서버 실패/성공을 구분한다. 서버 저장 응답을 확인하지 않고 저장 성공을 표시하지 않는다.
- 긴 텍스트·표 넘침·작은 화면·한글/날짜/단위 표시·폼 라벨/포커스를 확인한다. 과한 꾸밈이나 무관한 화면 대신 필수 경로를 완성한다.
- React/Next가 실제 스택일 때만 관련 공식/선별 자료를 읽는다. 템플릿 전체를 완성물로 대체하거나 외부 테마 설치를 의무화하지 않는다.

## 서버와 권한

입력 형식과 업무 정책의 검증 책임을 구분한다. 역할/인증이 실제 요구면 서버에서 주체·동작·대상 범위를 검사하고 허용/거절을 실제 요청으로 확인한다. 버튼 숨김이나 클라이언트 역할 값만으로 보호하지 않는다. 역할이 없는 과제에 관리자 기능·인증 서비스를 추가하지 않는다.

데이터 불러오기/변경/내보내기가 있다면 원본·정규화·저장 위치와 실패/재실행 정책을 맞춘다. 같은 규칙을 프런트·서버에서 서로 다른 의미로 구현하지 않는다. UI 검증은 사용자 편의이며 서버 검증의 대체가 아니다.

## 제공 Browser 미리보기와 화면 유지

웹 확인은 제공 작업환경 내부의 Browser 미리보기로 한다. 서버를 요구된0.0.0.0에 바인딩하고 실제 준비 완료/포트·경로를 확인해 사용자에게 미리보기 입력값을 안내한다. 서버 터미널은 유지한다. 프로세스/HTTP 확인은 내부 터미널에서 할 수 있지만 화면 확인과 분리한다.

시작 전에 실제 개발 스크립트가 OS 브라우저나 별도 앱을 자동으로 여는지 읽는다. 프로젝트 자신의 자동 열기 옵션/호출만 제거하거나 창을 열지 않는 기존 실행 경로를 선택한다. open/xdg-open·Windows의URL열기·webbrowser.open 같은 외부 실행, 새 탭/팝아웃·원격 데스크톱·브라우저 자동 조작을 기본 검증 경로로 만들지 않는다. 새로 만드는 내부 UI의 탐색도 별도 창을 기본으로 열지 않는다. 실제 과제에서 지정한 별도 경로/예외가 있으면 그 허용 범위를 먼저 확인한다.

포커스/전체화면/감독 감지·권한·플랫폼 설정을 바꾸거나 비활성화해 화면 이탈을 숨기지 않는다. 미리보기 접속이 안 되면 포트·바인딩·서버 상태·경로와 제공 안내를 확인하고 반복 플랫폼 오류는 문제 신고로 안내한다. 외부 브라우저를 대신 열거나 허용 호스트/감독 설정을 무작정 풀지 않는다. 이 방법이 경고를 절대 방지한다고 보장하지 않는다.

## 통합·배포 준비

프런트 mock과 서버 단위 테스트 통과 뒤 실제 입력→요청→처리/저장→재조회까지 확인한다. 권한이 있으면 허용/거절 경로도 검사한다. 허용된 수동 미리보기의 입력·기대값을 안내하고 실제로 보지 않은 화면을 확인했다고 쓰지 않는다.

클라우드 실행 조건이 실제 요구/예정이면 [배포 준비](references/cloud-readiness.md)를 읽는다. 로컬 준비와 실제 배포는 별도이며, 공개 준비물 사용 허용을 외부 배포 허용으로 해석하지 않는다. 시험의 외부 전송 금지와 충돌하는 전송은 하지 않는다.


## 가벼운 사용성 확인

표시만 보는 대신 필터/입력→실제 요청→결과/저장→재조회/내보내기를 한 번 이어 본다. 기본 스타일은 AI가 정리하되 전체 페이지 가로 잘림·겹침, 읽기 어려운 오류·상태, 조작하기 어려운 폼은 고친다. UI 내부 값이나 접힌 영역에 대한 검사 도구의 가정이 잘못된 경우 앱 결함과 구분한다. 실제 UI 조작 기준으로 검사를 바로잡고 실패 이력은 남긴다. 로컬 모의실험의 자동 브라우저 점검을 시험에서 허용된 도구로 일반화하지 않는다.
