# 클라우드에서 실행할 수 있게 준비하기

과제의 제공 배포 경로·서비스·제약부터 확인한다. 플랫폼 내부 배포가 명시적으로 제공되면 그 계약을 따르며 외부 계정·임의 호스팅을 만들지 않는다. 외부 전송 금지와 충돌하거나 경로가 불명확하면 설정/실행 안내까지만 준비하고 배포는 미수행으로 남긴다.

| 항목 | 실제 점검 |
| --- | --- |
| 재현 가능한 실행 | 실제 런타임·패키지 관리자·lock·빌드/시작 명령; 기존 스택 유지 |
| 주소/설정 | 제공 PORT·필요한 0.0.0.0 바인딩·API base·허용 origin; 비밀값은 환경 주입 |
| 정적/클라이언트 설정 | 서버 전용 비밀이 브라우저 번들에 포함되지 않는지, 경로/새로고침이 실제 환경과 맞는지 |
| 상태/파일 | 로컬 임시 파일·메모리의 재시작/다중 프로세스 한계; 필요한 영속 저장·마운트·초기 데이터 정책 |
| 오류/운영 | 실제 준비 상태 검사·로그·종료 처리·실패 응답; 필요 없는 운영 인프라는 추가하지 않음 |
| 배포 검증 | 제공된 배포 경로·실제 수행 여부·시작/접속/저장·재시작 결과; 미배포를 배포 성공으로 표시하지 않음 |

컨테이너가 필요하면 기존 Dockerfile/ignore·빌드 문맥·비루트 실행 지원·설정 주입·실제 실행 명령을 확인한다. Docker/Kubernetes/관리 DB는 기본 필수가 아니다. 기존 작은 서비스에 기능을 늘리지 말고 현 구조의 배포 한계를 정확히 설명한다.


저장 파일/볼륨이 없다는 상태와 읽기 권한·I/O·손상 오류는 구분한다. 실제 부재에만 원문이 허용한 초기화를 적용하고 다른 읽기 실패를 정상 빈 상태로 바꾸지 않는다. 재시작/접근 실패 뒤 기존 상태를 덮어쓰지 않는지 확인한다. 파일 저장의 원자성만 검사하고 복구/초기화 경계를 누락하지 않는다.
