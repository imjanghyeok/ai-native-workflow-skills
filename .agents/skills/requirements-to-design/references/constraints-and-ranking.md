# 우선순위·제약·스케줄·비용 과제

## 문제를 수식보다 먼저 정의

- 결정할 대상과 입력 단위, 현재 상태, 출력 형식.
- 반드시 지킬 제약과 개선할 목적: 납기·가동률·비용·위험 중 실제 우선순위.
- 가용 자원·시간 구간·선행관계·작업 분할/중단 허용 여부.
- 비교 기준·동률 처리·제약을 만족할 수 없을 때의 출력.

정책이 없으면 업무 질문으로 남기고 필요한 가정만 명시한다. 임의 가중치를 공식 평가 기준처럼 쓰지 않는다.

## 방법 선택과 검증

1. 먼저 제약 검사와 실행 가능한 단순 기준안을 만든다. 사이클·존재하지 않는 선행 작업·사용 불가 자원·시간 충돌처럼 결과 생성 자체를 막는 입력을 처리한다.
2. 입력 규모·시간·정확성 요구에 맞게 정렬/탐욕·힙·그래프·작은 완전탐색 등을 비교한다. 새 최적화 라이브러리를 제공받았다고 가정하지 않는다.
3. 생성한 결과를 별도 검증으로 제약과 대조한다. 위상 순서가 있다고 자원/마감 조건까지 충족하는 것은 아니다. 불가능한 입력을 조용히 누락하지 않는다.
4. 목표값을 같은 단위로 계산하고 단순 기준안과 비교한다. 휴리스틱을 최적해라고 주장하지 않는다. 작은 입력의 수동/완전탐색 정답과 비교할 수 있으면 활용한다.
5. 동률·입력 순서 변경·0자원·순환·겹치는 일정 등 실제 요구 위험을 확인한다. 비용 과제는 요금 구간·기간·최소 유지 자원·순간 최대 사용량 조건을 함께 확인한다.

## 인계

규칙/가정 → 방법 → 결과 제약 검증 → 기준안 대비 목표값 → 보장하지 못하는 경우를 연결한다. ‘절감’·‘개선’은 비교 대상과 수치의 근거가 있어야 한다. 상관관계를 장애 원인이나 최적 정책으로 단정하지 않는다.
