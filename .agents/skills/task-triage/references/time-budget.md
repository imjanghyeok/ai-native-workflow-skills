# 남은 시간으로 분담·검증·제출 예산 정하기

2026-11-05 재응시 안내의 전체 운영시간은19:00~23:00, 과제 최대180분, 준비 대기 약5분, 후속6문항×5분이다. 23:00 전체 종료는 늦은 입장/응답 대기로 연장되지 않는다. 이 날짜/시각을 다른 회차에 자동 적용하지 말고 최신 안내와 실제 화면을 우선한다. 에이전트 응답 대기를 고려한 위임/시간 안배도 평가에 포함된다고 안내한다.

## 시작 때 필요한 사실

실제 화면/사용자가 알려준 현재 시각, 과제 남은 시간 또는 실제 마감, 전체 종료, 후속 시간·대기·완료 여유를 구분한다. AI는 화면 타이머를 본 것처럼 추측하지 않는다. 값이 없으면 처음 한 번 요청하고, 답이 없어도 독립적인 원문 분석은 진행한다. 과제 시작을 clone/Codex 실행 시각과 같다고 가정하지 않는다. 확인된 기준과 출처, 불확실한 추정은 기존 계획/보드에 짧게 남긴다.

## 예산과 권장 전환 시점

- 과제 목표 종료 = 실제 과제 마감과 (전체 종료−후속30분−계획상 대기/완료 여유) 중 이른 시점. 준비 대기는 약5분 안내지만 변동할 수 있으므로 고정 보장하지 않는다. 예: 대기10분+완료여유5분을 잡으면 후속 포함45분을 확보한다. 이는 준비 전략이지 운영팀의 추가 제한/보장 대기시간이 아니다.
- 그 목표에서 제출 미리보기/저장 충돌/확정 준비10~15분, 통합·리뷰·핵심 실패 검증30~40분을 먼저 떼고 구현 가능한 예산을 계산한다. 충분한 시간일 때의 권장 예산이며 늦게 시작해 이보다 짧으면 중요도 순으로 줄이고 부족/미확인을 숨기지 않는다.
- 예:19:00 과제 시작/실제180분이면 과제 목표22:00, 새 기능 중단21:10~21:20, 핵심 통합/리뷰21:45~21:50까지, 이후 제출 준비. 실제 남은 시간/플랫폼 안내가 다르면 다시 계산한다. 후속 시작 버튼은 준비 완료 후 사용자가 누르고 모든 단계는23:00 전에 마친다.
- 사용자에게 근거 시각·과제 남은 시간·새 일감 중단 시점·검증 시작·제출 준비 시점을 짧게 제시한다. 고정 스케줄러/자동 제출이나 매분 상태 로그를 만들지 않는다.

## Terra 작업은 완료까지 걸릴 시간으로

Sol이 요구/계약/TODO/기대값을 정리한 다음, 전달·대기·구현·인계·통합·수정 확인까지 구현 예산 안에 들어오는 작은 독립 일감만 발급한다. 소요시간은 관찰 또는 계획 추정으로 구분한다. 병렬 실행이 항상 빠르거나 Terra가 항상 빠르다고 가정하지 않는다. 합류가 늦거나 공통 계약이 흔들리면 줄이거나 Sol에 합치고 파일 소유자를 명시적으로 인계한다. 기존 작업자가 쓰는 파일을 다른 담당이 동시에 고치지 않는다.

각 실행 카드에는 기준 시각/남은 예산·합류 목표·미완료 시 인계할 현재 파일/실행/실패/남은TODO와 더 확장하지 않을 범위를 넣는다. 워커가 실제 시각을 알 수 없다면 마감이 지났다고 추정하지 않고 진행 상태를 인계한다. 승인 대기/정상 실행/완료와 반복 모델API 오류를 구분하고, 응답이 늦다는 이유로 중복 작업·모든 프로세스 종료·다른 모델 무단 대체를 하지 않는다. 반복 플랫폼 오류는 문제 신고로 안내한다.

## 재계산과 마감 보호

Terra 인계, 예상보다 긴 대기/실패, 중요한 계약 변경, 리뷰 종료처럼 실제 의미가 있는 시점에만 예산을 갱신한다. 남은 시간이 줄면 미완료 필수를 우선하고 선택 UI/추상화/큰 리팩터링/새 의존성을 줄인다. 사용자와 범위 조정이 필요하면 영향·선택지를 짧게 올린다. 필수 기능을 몰래 제외하거나 검증 실패를 통과로 바꾸지 않는다.

검증 구간에는 대표 정상 end-to-end와 데이터/권한/저장·실패의 실제 위험을 우선한다. 중요한 결함만 최소 수정 후 관련 회귀/통합을 확인하고 현재 코드·로그·코드맵을 맞춘다. 제출 구간에는 새 기능을 멈추고 필수 파일·실행 안내·저장 상태·전체10GB 이하·미완료/한계를 확인한다. 제출 확정 뒤 수정 불가와 후속AI/복붙 금지를 안내하고 본인이 최종 종료 화면까지 확인한다. 실제 제출 클릭/외부 전송은 이 문서가 승인하지 않는다.
