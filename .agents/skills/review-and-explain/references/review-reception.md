# 리뷰 제안을 받아들이기 전에

이 문서는 `obra/superpowers`의 review reception 기준을 필요한 부분만 한국어로 재구성했다. 원문·고정 커밋·제외한 규칙·MIT 고지는 [선별 목록](../../task-triage/references/public-sources.md)과 [THIRD_PARTY_NOTICES](../../../../THIRD_PARTY_NOTICES.md)에 있다. 원문 전체 스킬·런처·다른 스킬 호출을 설치하지 않는다.

1. 지적이 실제로 어떤 요구/실패를 말하는지 확인한다.
2. 현재 코드·호출부·실제 지원 환경·테스트에 적용되는지 재현하거나 정적으로 근거를 좁힌다.
3. 기존 계약이 깨지거나 불필요 기능이 추가되는지 판단한다. 모호한 일부 항목만 막히면 독립된 나머지 검증은 진행한다.
4. 유효한 결함은 담당 소유자가 수정하고 관련 검증을 실행한다. 근거가 부족하면 보류, 틀린 전제면 이유와 함께 거절한다.
5. 결과를 제안/결정/변경/검증으로 연결한다. 리뷰어 권위나 동의 표현을 근거로 삼지 않는다.

| 분류 | 처리 |
| --- | --- |
| 확인된 계약 위반 | 재현/원문 근거 → 수정 → 재검증 |
| 미정 업무 정책 | 판단 대기·선택지·영향; 사용자 확정을 꾸미지 않음 |
| 방어/성능 보완 | 실제 위험·범위·시간과 비교해 채택/보류 |
| 선호/오탐 | 현재 계약과 대조한 이유로 거절/유지 |

원문의 모든 불명확 항목에서 전체 작업 중단, 자동 서브에이전트 호출, 고정 승인/커밋 절차는 이 묶음에 채택하지 않았다. 이 프로젝트는 필요한 경계 안의 자율 진행을 우선한다.
