# 제안·선택·거절의 근거

결정마다 모든 항목을 채우는 관리 업무를 만들지 않는다. 중요한 업무/설계/계약 선택을 기존 `docs/decisions.md`에 축적한다.

| 항목 | 기록 기준 |
| --- | --- |
| 결정 ID·관련 요청/R-ID | 실제 근거로 연결 |
| 상태·시점 | 제안/채택/수정 채택/거절/보류/대체; 사후 정리는 retrospective |
| 제안자·결정자 | user 직접 발언, AI 제안, AI 재량 결정을 구분; 세션 ID 포함 가능 |
| 문제·대안 | 해결할 충돌, 현재 방식 유지도 가능한 대안 |
| 선택 이유 | 정확성·구현 시간·성능·배포·유지보수 등 실제 기준 |
| 이점·비용·한계 | 장점만 나열하지 않고 잃는 것·미검증도 기록 |
| 확정 근거 | 직접 발언/기존 지시/기술적 재량 범위; 사용자 확인 없는 것은 미확정 |
| 적용·검증 | 실제 파일/심볼·관련 일감·명령/출력; 계획과 완료 분리 |
| 재검토 조건 | 어떤 입력 크기·정책 변경·실패 시 결정을 바꿀지 |

거절 제안은 제안 내용·거절한 주체·구체적 이유·대체 방법·근거를 보존한다. AI가 제안을 철회한 것과 사용자가 거절한 것은 다르다. 거절이 없으면 `없음`으로 쓰고 평가를 위해 만들어내지 않는다. 판단을 기록했다고 성능이나 정확성이 검증되는 것은 아니다.

원문에 이미 명시된 요구는 출처 문서로 연결하고 다시 사용자 승인 대기에 올리지 않는다. 요구의 확정 여부, 수정할 권한, 실제 반영 여부는 별개다. 분석만 요청된 경우 확정 결함도 수정하지 않지만, 그 이유는 `정책 미정`이 아니라 `이번 범위는 분석`이다. 아직 결정되지 않은 업무 정책의 결정자를 사용자로 채워 넣지 않는다.
