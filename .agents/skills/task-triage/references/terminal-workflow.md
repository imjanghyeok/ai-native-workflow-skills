# 느린 터미널에서 지시와 실행을 관리하기

이 가이드는 명령 왕복·불필요한 설치·재작업을 줄이려는 작업 방식이다. Codex 자체 추론 속도나 서버 지연을 해결한다고 보장하지 않는다. 실제 도구 권한과 승인 요청은 그대로 따른다.

## 한 번에 맡길 작업의 크기

- 명령 하나씩 지시하기보다 ‘목표 + 수정 범위 + 유지할 계약 + 완료 기준 + 실제 검증’으로 작은 업무 단위를 맡긴다.
- 최초에 필요한 파일·버전·기존 명령을 묶어 확인하되, 의존하는 작업은 앞 결과를 보고 이어간다. 로그·파일을 무한히 출력하거나 저장소 전체를 반복해서 읽지 않는다.
- 한 업무 단위가 끝나면 변경 파일, 충족한 요구, 실제 실행 결과, 미완료와 다음 행동을 짧게 받는다. 매 줄 승인을 요구하는 흐름을 만들지 않는다. 진행을 막는 질문과 일상적 구현 선택을 구분한다.

## 사용자가 파일을 직접 조작하기 불편한 환경

사용자 대신 Codex가 디렉토리 구성·파일 생성·필요한 이동/삭제·코드 수정을 수행한다. 사용자의 조작 불편을 AI 파일 조작 금지로 해석하지 않는다. 원본 데이터·사용자 변경·기존 계약을 보호하면서 필요한 작업은 진행한다. 관리 영역이나 실제 플랫폼 권한을 우회하지 않는다.

[자동 구조·기록 도구](workspace-and-records.md)로 문서·데이터·도구·작업 로그 위치를 준비할 수 있다. 기존 파일이 충돌하면 도구가 덮어쓰지 않으므로 Codex가 내용을 읽고 병합·이동 등 필요한 처리를 판단한다. 사용자가 탐색기에서 직접 파일을 만들도록 떠넘기지 않는다. 임시 파일·백업이 제출물과 실행 경로를 혼란스럽게 만들지 않게 한다.

## 설치와 서버

기존 프로젝트의 잠금 파일·명령·버전을 우선한다. 새 프로젝트라면 이미 있는 런타임과 표준 기능으로 필수 업무를 끝낼 수 있는지 먼저 본다. 스킬 사용을 위해 MCP·별도 모델·글로벌 패키지를 설치할 필요는 없다.

개발 서버는 유지하고 필요한 검증은 별도 명령/터미널에서 실행한다. 느리다는 이유로 모든 터미널·프로세스·감독 연결을 종료하지 않는다. 설치/실행이 실패하면 원인과 가용 대안을 좁히고 같은 명령을 근거 없이 반복하지 않는다.

## 중간 보고 요청 예

‘이번 단위의 R-ID와 기대 동작, 변경 파일과 실제 검증 결과를 알려줘. 유효한 이전 결과는 재사용하고 아직 확인하지 않은 범위는 분리해 줘. 정상적으로 진행 가능한 작업은 이어가고, 계약 충돌이나 필요한 정보가 없을 때만 질문해 줘.’
