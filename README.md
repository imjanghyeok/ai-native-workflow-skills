# AI Native Workflow Skills

README 기반 과제를 파악하고, 요구사항·데이터·설계·코드·검증 근거를 연결하기 위한 한국어 Codex 스킬 묶음입니다. 특정 언어·프레임워크·MCP·외부 모델을 필수로 사용하지 않습니다.

**바로 사용하기:** [clone 명령](#1-응시-화면-안에서-가져오기) → [단계별 복사 프롬프트](#2-단계별-복사-프롬프트-설치-없이-사용).

데이터가 있는 과제는 **단계 1 → 데이터 탐색 → 단계 2·3 → 단계 4에서 데이터 가공 → 단계 5 대조·검증** 순서로 적용합니다. [현재 준비 상태](#현재-준비-상태)도 확인할 수 있습니다.

## 포함된 스킬

| 순서 | 스킬 | 용도 | 기본 산출물 |
| --- | --- | --- | --- |
| 1 | `readme-to-requirements` | README·관련 자료 분석, 필수 조건·출처·완료 기준·가정·질문 정리 | `docs/requirements.md` |
| 데이터가 있을 때 | `data-to-validated-dataset` | 자료 탐색·추출·정규화·중복/충돌 처리·결합·집계·원본 대조 | 기존 문서의 데이터 절, 필요시 `docs/data-notes.md`; 가공 요청 시 코드·데이터·검증 근거 |
| 2 | `requirements-to-design` | 최소 설계, 필요한 Mermaid 다이어그램, 자료구조·알고리즘 선택, 검증 계획·구현 순서 | `docs/design.md` |
| 3 | `implement-and-verify` | 프로젝트 컨벤션에 맞춘 구현, 실제 실행·검증, 설명 근거와 한계 기록 | 코드와 `docs/verification.md` |

기존 문서와 제출 양식이 있으면 해당 위치·형식을 우선합니다. 분석만 요청했으면 구현까지 진행하지 않고, 구현까지 요청했다면 불필요한 승인 대기 없이 요청 범위에서 이어갑니다.

## 시험 환경에서 clone해서 사용하기

시험 내 스킬 반입·공개 자료 사용이 허용되는지 먼저 확인하세요. 공개 개인 MCP 설정 반입 허용이 범용 스킬 묶음 전체의 반입 허용을 자동으로 의미하지는 않습니다. 실제 응시 안내와 제공 도구 제한을 따릅니다.

### 1. 응시 화면 안에서 가져오기

개인 PC 파일 업로드 대신, 허용된 경우 **응시 환경의 터미널과 제공 AI**로 가져옵니다.

```sh
git clone --depth 1 -- https://github.com/imjanghyeok/ai-native-workflow-skills.git /home/user/exam-kit
git -C /home/user/exam-kit rev-parse HEAD
ls -a /home/user/exam-kit/.agents/skills
```

`/home/user/exam-kit`은 가져온 스킬을 두는 예시 위치이며 과제 폴더와 구분합니다. 이미 그 폴더가 있다면 내용을 확인하고 다른 빈 경로를 사용하세요. 기존 과제·설정·파일을 삭제하거나 덮어쓰지 않습니다. 가져온 커밋 ID를 남겨 어떤 준비물을 사용했는지 확인할 수 있게 합니다.

제공 AI에게 요청할 예:

```text
공개 저장소 https://github.com/imjanghyeok/ai-native-workflow-skills.git 를
/home/user/exam-kit 에 clone해 줘. 폴더가 이미 있으면 덮어쓰지 말고 상태를 알려줘.
가져온 README와 스킬 목록을 확인하고 커밋 ID를 알려줘.
과제 파일·AGENTS.md·Codex 설정 전체는 변경하지 마.
```

### 2. 단계별 복사 프롬프트 (설치 없이 사용)

clone을 마친 뒤 **실제 과제 폴더에서** 제공 Codex를 실행합니다. 터미널에서 실행하는 환경이라면 명령은 `codex`입니다. 이미 Codex가 실행 중이면 그 대화에서 이어가세요.

아래 코드 블록을 **한 단계씩 복사**하고, 결과를 읽은 뒤 다음 단계로 진행하세요. `/home/user/exam-kit`을 다른 위치로 바꿨다면 프롬프트의 경로도 바꿉니다. 자동 스킬 설치나 MCP 연결 없이, 스킬 파일을 읽어 절차를 적용하는 방식입니다. 상대 경로로 연결한 `references/` 문서는 해당 스킬 폴더를 기준으로 읽습니다.

```text

적용되는 AGENTS.md, 과제 README·안내, 기존 코드·데이터·테스트·실행 설정을 읽어 줘.

제공 자료의 예시를 이번 과제의 필수 요구사항으로 단정하지 마.
이번 단계는 분석만 하고 제품 코드는 수정하지 마.
```

#### 데이터가 있는 경우 · 단계 1 뒤에 탐색만 수행

CSV·JSON·로그·스프레드시트·PDF 등 제공 자료가 업무 입력일 때만 적용합니다. 이 요청은 구조와 품질을 조사하는 단계이며 가공 실행 단계와 구분합니다.

```text
/home/user/exam-kit/.agents/skills/data-to-validated-dataset/SKILL.md를 읽고 적용해 줘.
이번에는 데이터 탐색과 규칙 정리만 해 줘. 원본을 바꾸거나 가공 코드를 구현하지 마.
가공 결과 파일 생성·패키지 설치·설정 변경도 아직 하지 마.

과제에 필요한 제공 자료부터 파일·시트·형식·규모와 작은 표본을 확인해 줘.
한 행/항목의 의미, 필드·타입·단위·날짜/시간대·키 후보와 출처 위치를 정리해 줘.
원본값과 정규화값, ID 선행 0, 0/null/빈 값, 비율과 퍼센트를 구분해 줘.
중복·상충 ID·잘못된 값·누락·파싱 실패 가능성을 확인하고,
여러 자료를 연결한다면 키 관계·미매칭·행 증식 위험을 짚어 줘.
표본으로 본 것과 전체를 실제 검사한 결과를 구분하고 수치를 추측하지 마.

필요한 추출·정제·결합·집계 규칙과 원본 대조 계획을
확정·가정·미정으로 나누고, 판단에 필요한 업무 질문을 초안으로 남겨 줘.
도구가 없어 읽지 못한 형식이나 범위도 표시해 줘.
기존 요구사항 문서에 데이터 절로 정리하고,
별도 문서가 필요할 만큼 크면 실제 과제 폴더의 docs/data-notes.md에 정리해 줘.
```

```text

- 검증할 정상·실패·경계 사례

데이터 탐색 결과가 있으면 입력 단위·키·타입·단위·변환 규칙·대조 기준도 연결해 줘.
```

```text

내가 보낸 질문: [실제 질문]
받은 답변: [실제 답변]
```

#### 단계 4 · 컨벤션에 맞춰 구현하고 중간 검증

```text
/home/user/exam-kit/.agents/skills/implement-and-verify/SKILL.md를 읽고 적용해 줘.
과제 README·요구사항·설계에 따라 필수 업무 흐름부터 구현해 줘.

제품 코드를 수정하기 전에 적용되는 AGENTS.md, 프로젝트 지침,
포맷터·린터·타입·테스트·빌드 설정, 주변 구현을 확인하고

기존 응답 계약과 사용자의 변경을 보존하고 불필요한 전체 재작성은 피해야 해.
검증 실패는 원인을 확인해 고치고, 요구사항·설계가 바뀌면 관련 문서도 갱신해 줘.
명령·실제 결과·실패 원인·미확인 범위를 구분해서 기록해 줘.
실행하지 않은 검증을 통과했다고 쓰지 마.

이미 요청한 구현·검증은 불필요한 승인 대기 없이 진행하고,
진행을 막는 요구사항 충돌이나 꼭 필요한 정보가 없을 때만 질문해 줘.
```

#### 데이터가 있는 경우 · 단계 4에서 가공 구현·실행

데이터 처리가 필수 업무 흐름이면 아래 블록을 **단계 4 프롬프트와 함께** 입력하세요. 단계 4에서 이미 처리한 작업은 반복하지 않고 부족한 부분만 보완합니다.

```text
/home/user/exam-kit/.agents/skills/data-to-validated-dataset/SKILL.md도 적용해 줘.
앞서 확인한 원본·요구사항·설계의 규칙을 기준으로 필요한 데이터 처리를 구현하고 실행해 줘.
기존 컨벤션을 따르고, 과제에 없는 변환·결측 보정·충돌 정책을 임의로 확정하지 마.

추출 → 필요한 정규화·검증 → 중복/충돌 처리 → 결합 → 집계 중
과제에 필요한 단계만 구현해 줘. 단위와 처리 순서는 실제 계약에 맞춰 줘.
원본은 보존하고 기존 제출 구조에 맞는 별도 위치에 결과와 제외 사유를 남겨 줘.
원본 파일·시트·행·객체 경로·문서 쪽 등 가능한 출처를 추적할 수 있게 해 줘.

작은 원본 입력으로 독립적인 기대값을 만들고 실제 출력과 대조해 줘.
채택/제외·중복/상충·매칭/미매칭 건수와 결합 전후 행 수·합계를
실제로 확인한 범위에서 기록하고, 가공별로 왜 변했는지 설명해 줘.
모든 단계에서 행 수가 같아야 한다고 가정하지 마.
분자·분모, 0 분모, 단위 변환과 결합 중복 집계에 특히 주의해 줘.
출력을 다시 읽어 타입·ID·null·인코딩을 확인하고,
재실행 때 중복 누적되거나 원본이 변경되지 않는지도 확인해 줘.

재실행 명령·실제 결과·미확인 범위를 기존 데이터/검증 문서에 연결해 줘.
추출 도구가 없거나 원본과 대조하지 못한 값을 검증 완료라고 쓰지 마.
```

#### 단계 5 · 최종 검증과 제출·설명 준비

```text
원본 README와 요구사항 ID를 기준으로 현재 제출물을 최종 점검해 줘.
요구사항별 구현 위치, 실제 검증 근거, 충족 여부와 남은 한계를 연결해 줘.
유효한 기존 검증 결과는 재사용하고, 변경된 부분·미검증 부분·중요한 위험을 우선 확인해 줘.
데이터 가공이 있었다면 원본 출처·건수/합계 대조·제외 이유·재실행 근거도 확인해 줘.

실제 실행 방법, 필요한 설정, 테스트 명령과 결과를 다른 사람이 재현할 수 있게 정리해 줘.
웹 서비스라면 실제 서버 포트·경로와 0.0.0.0 바인딩 필요 여부를 확인해 줘.
브라우저 확인은 현재 환경에서 허용된 수동 미리보기 등으로 진행하고,
확인할 수 없거나 내가 아직 확인하지 않은 화면 동작은 미확인이라고 표시해 줘.
시험에서 금지된 Computer Use나 외부 모델 연결을 사용하지 마.

기존 검증 문서·제출 양식이 있으면 우선하고,
없으면 실제 과제 폴더의 docs/verification.md에 기록해 줘.
제출 대상 파일과 실행 안내 누락도 확인하되 최종 제출 확정은 내가 직접 할게.

마지막으로 내가 직접 설명할 수 있도록
핵심 선택·이유·코드 및 실행 근거·한계를 짧게 정리해 줘.
AI가 수행한 일과 내가 직접 확인하거나 판단한 일을 혼동하지 마.
```

과제 산출물은 clone한 스킬 폴더가 아니라 **실제 과제 폴더**에 작성합니다. 각 단계의 문서와 코드는 본인이 읽고 확인하세요. 위 프롬프트는 AI 사용이 허용된 과제 작업 단계용이며, **AI·복사·붙여넣기가 금지된 후속 서술형 단계에서는 사용하지 않습니다.**

### 3. Codex 스킬 목록에서 사용하고 싶다면

일반 Codex는 현재 작업 위치부터 저장소 루트까지 `.agents/skills`를 검색합니다. 과제 옆의 다른 폴더에 clone하는 것만으로 과제에서 자동 발견되는 것은 아닙니다.

환경에서 허용하면 제공 AI에게 다음처럼 요청하세요.

```text
가져온 스킬을 현재 과제에서 사용할 수 있는지 확인해 줘.
현재 작업 경로와 기존 .agents/skills 및 동명 스킬을 먼저 확인하고,
필요한 스킬 폴더만 작업 범위에 맞춰 추가해 줘.
기존 스킬·AGENTS.md·Codex 설정 전체를 덮어쓰지 마.
```

스킬이 인식되면 `/skills` 또는 `$`로 선택해 사용할 수 있습니다.

```text
$readme-to-requirements 현재 과제 README를 분석하고 요구사항을 정리해 줘.
$data-to-validated-dataset 이번에는 제공 자료를 탐색하고 데이터 계약과 가공·대조 계획만 정리해 줘.
$requirements-to-design 정리된 요구사항의 최소 설계와 다이어그램을 만들어 줘.
$implement-and-verify 설계와 기존 컨벤션을 따라 구현하고 실제 검증 근거를 남겨 줘.
```

제공 Codex 버전에 따라 지원·인식 방식이 다르면 앞의 파일 경로 방식으로 절차를 읽히거나 Helper에 환경 사용법을 확인하세요. 공식 문서: [Codex Skills](https://developers.openai.com/codex/skills).
