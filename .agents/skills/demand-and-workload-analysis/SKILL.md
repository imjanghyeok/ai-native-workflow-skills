# 관측 데이터를 수요·작업량으로 연결

## 먼저 정의할 계약

원문 요구/데이터 출처에서 한 행의 의미와 결정 단위를 정한다. 요청·예약·실제 이용·완료·취소·재시도는 다르다. 관측된 처리량을 전체 수요라고 가정하지 않는다. 중복/누락/상충은 data-to-validated-dataset으로 확인하고 기존 데이터 계약을 재사용한다. 파일이 있다는 이유로 UI/예측/최적화 기능을 추가하지 않는다.

- 어떤 대상이 언제 어떤 양/자원을 요구하는가: 시간 구간·방향/집단·위치/자원 등 실제 필요한 차원만 고른다.
- 건수·고유개체·수량·작업시간·동시점유 중 무엇을 측정하는가. 단위/기간/분모·취소/미처리·중복 규칙을 명시한다.
- 서비스 가능 시간·자원 용량·처리시간·재사용/전환/회복시간은 제공 자료와 업무 정책에서 확인한다. 없으면 추정과 질문으로 남긴다.

## 분석과 전처리 영향

[필요한 탐색](../data-to-validated-dataset/references/bounded-eda.md)을 적용하되 전체 통계 보고서를 의무 생성하지 않는다. 시간/그룹별 합계와 원본 채택 합계를 대조한다. 기간 길이/노출량이 다른 집단은 총량만으로 비교하지 않는다. 시간대·휴일·시간대변환·경계 포함을 명시하고 중복 결합으로 요청량을 증식시키지 않는다.

평균 외에 실제 위험에 관련된 피크·분위수·최대 동시 작업량·미충족을 확인한다. 누적 총량과 순간 동시 용량, 수행 횟수와 물리 자원 수를 구분한다. 시간 중첩·재사용·선행관계 때문에 총량/용량을 나눈 값만으로 실행 가능한 배정을 보장할 수 없다. 특정 집단 결측/제외가 수요를 과소평가하는지 확인하고 관측 불가를0으로 처리하지 않는다.

## 관측·예측·시나리오 분리

확인된 수요, 관측된 완료량, 예측값, 가정으로 만든 증감 시나리오를 구분한다. 예측이 요구되지 않으면 집계와 명시적 시나리오로 충분할 수 있다. 예측이 필요할 때만 기존값/단순계절 기준과 시간순 검증을 먼저 준비한다. 미래 정보 누수·학습/평가 구간·오차·미관측 범위를 확인하고 모델 이름으로 성능을 보장하지 않는다.

시나리오 변경 폭과 선택 이유는 가정이다. 데이터가 없는 수치/확률/정책을 관측이나 사용자 확정으로 만들지 않는다. 실제 우선순위가 필요한 임계값/최소 서비스/집단 형평성 질문은 Sol이 모아 사용자·현업 판단과 기술 재량을 구분한다.

## 완료 근거와 인계

기존 분석/설계에 관측기간/범위·단위·그룹별수요/용량·원본대조·미충족/불확실성·가공 영향·다음 결정에 쓰일 값을 남긴다. 입력/설정/출처 버전이 같은지 확인한다. 0수요/결측집단/피크/동시성 중 실제 위험의 작은 입력과 독립 기대값을 검증한다. 미실행을 실제 결과로 쓰지 않는다.

배분/일정/추천을 결정해야 하면 [운영안 선택 스킬](../optimize-and-compare-plans/SKILL.md)로 목표·제약·기준안과 연결한다. 핵심 수요 해석/정책은 Sol이 정리하고, Terra에는 정의된 집계/계산/API와 테스트 범위만 전달한다.

입력 크기는 유효 요청 수뿐 아니라 등록 기간/그룹/자원·중간 펼침 크기도 확인한다. 요청이 없더라도 큰 기준 목록을 순회·집계할 수 있으므로 원문이 허용한 범위를 임의로 줄이지 않는다. 대량 값을 함수 인수로 펼치는 등 런타임 한계를 피하고, 피크/합계는 필요한 순회·누적 방식으로 계산하며 실제 관련 경계만 검증한다.
