# 요구사항 문서에 남길 정보

문서 형식보다 추적 가능성이 중요하다. 아래 항목 중 과제에 해당하는 것만 사용한다.

- **업무 목표:** 사용자 / 입력 / 끝나야 할 업무 / 제외 범위.
- **필수 제출·실행 계약:** 제출 파일과 경로, 실행 명령, 입출력, 유지해야 하는 기존 응답·동작, 수정 금지 사항.
- **요구사항 표:** ID | 요구사항 | 필수·권장·선택 | 출처 | 확정·가정·미정 | 관찰 가능한 완료 기준.
- **현재 코드와의 차이:** 관련 파일·함수 | 코드에서 관찰한 사실 | 아직 실행 확인하지 않은 부분. 버그 수정 과제는 보고된 현상과 재현 여부를 구분한다.
- **질문·충돌:** 질문 ID | 출처 양쪽 | 답에 따라 달라지는 구현/검증 | 대상 역할 | 현재 상태. 중요 질문을 우선 배치한다.
- **최소 완료 범위:** 필수 기능의 가장 작은 연결 흐름. 제외한 필수 요구가 있다면 충족이 아닌 미완료로 표시한다.

완료 기준의 예: ‘오류를 잘 처리한다’ 대신 ‘잘못된 헤더 입력에 대해 원문에서 정한 오류 처리를 하고 성공 결과를 표시하지 않는다’. 원문에 오류 메시지·부분 처리 정책이 없으면 값을 발명하지 말고 미정으로 남긴다.

원문의 ‘API 응답 형식을 유지’와 기존 테스트의 상충은 충돌이다. 개발 편의를 이유로 응답 구조를 바꾸는 가정을 확정 조건으로 적지 않는다.
