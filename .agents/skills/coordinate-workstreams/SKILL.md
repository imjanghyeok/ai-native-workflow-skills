# 재량을 남기는 일감 분배

실제 사용자가 허용한 같은 작업 환경의 세션만 사용한다. 이 스킬은 새 계정·외부 에이전트·자동 세션 런처를 추가하지 않는다. 여러 세션 허용이 이미 확인됐다면 같은 허용을 반복해서 묻지 않는다. Sol/Terra의 우열이나 가용 ID를 추정하지 말고 실제 제공 모델과 현재 작업 난이도로 배정한다.

## 기본 역할 · Sol 판단, Terra 구현

사용자가 선택한 운영 전략으로 Sol은 요구 해석·설계·공통 계약·중요 오류 분석·통합을 맡고, Terra는 추가 판단이 적고 결과를 검증하기 쉬운 구현을 맡는다. 모델의 공식 전용 분야나 속도 우위를 뜻하지 않는다. API/CRUD라도 권한·트랜잭션·예외 정책이 미정이면 먼저 Sol이 정리한다.

Terra 전달 전에 Sol이 요구 ID, 구현 TODO, 입출력/오류·데이터/권한 계약, 수정 범위, 정상·실패·경계 입력과 예상 결과를 준비한다. 모든 테스트 코드를 선작성하거나 함수별 구현을 지시할 필요는 없다. 핵심 계약 테스트가 유효하면 Sol이 먼저 준비하고, Terra는 구현과 단위/경계/회귀 테스트를 보완한다. 계약 안의 구현은 Terra가 자율 진행하고 계약·업무 정책 변경이 필요하면 근거/대안을 Sol에 인계하며 독립 작업은 계속한다.

복잡한 설계·알고리즘·미정 정책을 반복적인 구현처럼 넘기지 않는다. Sol이 직접 처리하거나 충분히 쪼개 준비한 뒤 발급한다. 실제 실행·재작업을 포함한 완료 시간을 기준으로 분배를 조정하고, 느리거나 재작업이 많으면 단일 Sol로 합칠 수 있다. 속도 측정용 관리 절차를 추가하지 않는다.

## 경계만 먼저 정하기

- 통합 담당 하나가 원문 요구, 공통 계약, 의존성/잠금 파일, 전역 컨벤션, 전체 검증을 관리한다. 소규모 과제는 단일 세션으로 충분하다.
- 일감은 목표·R-ID·선행 조건·입출력/실패 계약·쓰기 범위·완료 기준·검증으로 정의한다. 구현 절차와 모든 함수를 미리 지정하지 않는다. [일감/판단 양식](references/work-board.md)을 필요할 때 사용한다.
- 프런트/백엔드의 독립된 변경 범위가 있으면 분리한다. 데이터 계약이 미정이면 각자 다른 정책을 구현시키지 말고 계약 조사나 읽기 전용 검토를 먼저 병렬화한다.
- 공통 파일마다 쓰기 소유자 하나를 둔다. 워커는 자기 파일만 쓰고 다른 범위가 필요하면 계약 변경을 제안한다. 변경 후 인계 전까지 해당 일감 상태를 알린다.

사용자가 세션별 복사 지시를 원하면 [분석 기반 세션 카드](references/session-packets.md)를 적용한다. 실제 요구·계약·쓰기 범위를 확인한 뒤 주작업 계속/Terra 일감/별도 리뷰의 완성 블록과 `지금 판단·지금 전달·직접 확인·다음 확인 조건`을 만든다. 분석 전에 고정된 일감을 배정하거나 카드 생성을 착수로 기록하지 않는다.

## 판단을 분리하기

사용자가 정한 목표·정책·예산·우선순위는 유지한다. 이미 맡긴 범위의 되돌릴 수 있는 구현·테스트·오류 수정은 진행한다. 사용자 지시도 코드·원문·실행 근거와 충돌하면 이유와 대안을 제시한다. 반대 횟수나 거절 기록을 성과로 만들지 않는다.

업무 의미의 변경, 요구 충돌, 중요한 정확도/비용/보안 절충, 실제 외부 배포 등 사용자 결정/권한이 필요한 사항은 `판단 대기`에 질문·선택지·추천·영향·기한을 모은다. 답이 필요한 부분만 멈추고 독립 작업은 이어간다. AI 제안을 사용자 확정으로 승격하거나 시간 경과를 승인으로 취급하지 않는다.

원문에 명시된 동작·상태 코드는 확정 요구다. 수정 권한이 없는 분석에서는 `확정 요구 위반·수정 미수행`으로 적고, 정책을 다시 확정받아야 하는 문제로 바꾸지 않는다. 업무 의미/계약을 바꾸지 않는 오류 문구·배치·파일명 등은 기존 컨벤션 안에서 AI 재량으로 진행한다. 사용자 직접 결정은 실제 발언/명시 지시가 있을 때만 기록하고, 문서에 적힌 미정 정책의 결정자는 `미정`이다.

[결정 기록](references/decision-records.md)에 제안자와 결정자를 따로 쓰고, 제안/채택/수정 채택/거절/보류/대체 상태를 구분한다. 기술적 자율 결정은 `AI 재량 결정`, 사용자 발언은 `사용자 직접 결정`으로 표시한다. 사용자에게 모든 사소한 변경을 승인받게 하지 않는다.

## 통합과 기록

중요한 계약·판단·실행·검증만 기록한다. 공유 보드·공통 문서·기존 `tools/worklog.cjs`의 공유 이벤트는 통합 담당 한 명이 쓴다. 다른 세션은 `worklog/handoffs/<일감ID>-<세션ID>.md`와 자기 실행 출력 경로에 작성하고 통합 담당이 출처로 연결한다. 기존 기록기는 다중 작성자 잠금/통합을 보장하지 않는다. 기록을 옮겨 적은 것과 직접 캡처한 것을 구분한다.

완성 일감은 `리뷰 대기 → 수정 필요/검증 완료`로 이동한다. 읽기 전용 리뷰는 대상 커밋/변경 파일 해시 등 실제 snapshot과 계약을 식별한다. 파일이 바뀌면 영향을 받은 부분을 다시 검토한다. 프런트·백엔드 각각 성공해도 통합 입력→저장/처리→응답이 완료됐는지 확인한다.

세션에 보낼 지시와 인계는 준비 저장소의 [SESSION-HANDOFF](../../../templates/SESSION-HANDOFF.md)를 필요한 만큼 사용한다. 네이티브 세션 메시징 기능이 없으면 사용자가 같은 환경의 다른 터미널에 복사할 일감 프롬프트를 제시한다. 전달하지 않은 지시를 전달했다고 쓰지 않는다.
