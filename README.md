## 느린 터미널에서 JS/TS로 시작하기

기본 준비 방향은 **JavaScript/TypeScript 중심, MCP 연결 없이, 기존 파일을 작은 단위로 수정하는 방식**입니다. 스킬은 AI가 일하는 절차이며 터미널 실행을 대신하거나 Codex 자체 지연을 해결하지는 않습니다. 명령 왕복·설치·불필요한 재작업을 줄이도록 준비했습니다.

| 실제 환경 | 선택할 기본값 |
| --- | --- |
| 기존 프로젝트 제공 | 언어·프레임워크·실행 스크립트·잠금 파일 유지. 다른 스택으로 재작성하지 않음 |
| 새 CLI/작은 데이터 도구 | Node.js 표준 기능, 입력/처리/출력 분리. 필요한 데이터 파서는 계약에 맞게 선택 |

## 자동 작업 공간과 요청·판단 로그

**사용자가 직접 파일을 조작할 필요가 없도록 Codex가 구조를 준비합니다.** AI의 생성·이동·필요한 삭제를 금지하는 방식이 아닙니다. 실제 과제의 원본·사용자 변경·관리 영역·계약을 보호하면서 필요한 작업은 수행합니다.

[자동 준비 도구](.agents/skills/task-triage/scripts/prepare-workspace.cjs)와 [사용 가이드](.agents/skills/task-triage/references/workspace-and-records.md)를 넣었습니다. 아래 블록을 clone한 뒤 Codex에 입력하면 됩니다.

```text
/home/user/exam-kit/.agents/skills/task-triage/references/workspace-and-records.md를 읽고 적용해 줘.
실제 과제 위치와 기존 README·AGENTS·코드 구조를 확인해 줘.
prepare-workspace.cjs를 실제 과제 위치에 실행해서 문서·데이터·도구·작업 로그 구조를 준비해 줘.
새 JS 과제라면 --starter js, 기존 프로젝트면 --starter none으로 시작해 줘.
충돌하는 기존 파일은 내용을 읽고 필요한 부분만 병합해 줘.
내가 탐색기에서 직접 파일을 만들거나 옮기게 하지 말고 필요한 파일 작업도 네가 처리해 줘.

각 요청의 원문을 로컬 worklog에 기록하고 requestId에
계획·선택·이유·대안·예상 결과·실제 결과·검증 근거·한계를 연결해 줘.
AI가 정리한 판단과 내가 직접 말한 생각을 actor로 구분해 줘.
기록 실패나 누락을 기록 완료라고 쓰지 말고, 실행하지 않은 사실은 만들지 마.
시험 자료와 로그를 git push·업로드·외부 전송하지 마.
```

생성 구조는 다음과 같습니다. 기존 프로젝트에서는 app/을 추가하지 않고 원래 코드 구조를 유지할 수 있습니다.

```text
실제과제/
  app/                         # 새 JS 과제일 때만
  docs/
    requirements.md
    design.md
    decisions.md
    verification.md
    WORKFLOW.md                # 생성된 기록 도구 사용법
  data/raw/
  data/processed/
  tools/worklog.cjs
  worklog/
    requests/                  # 요청 원문
    runs/                      # 요청/검증 실행별 입력·출력·종료 상태
    handoffs/
    events.jsonl               # 첫 기록 시 생성
```

‘사고과정 기록’은 **설명 가능한 선택·이유·대안·예상·근거·한계**로 구조화합니다. 본인이 남긴 생각은 actor=user, AI의 설명과 판단은 actor=ai로 구분합니다. AI가 사용자의 판단을 추측해 채우지 않습니다. 문서 템플릿이 생겼다는 사실만으로 실제 분석·구현·검증이 완료된 것은 아닙니다.

### 요청 원문을 먼저 저장하고 싶다면

일반 Codex 대화에서는 AI가 요청을 전사해 기록합니다. 이 방식은 모든 입력을 독립적으로 자동 포착하는 기능은 아닙니다. **제공 CLI가 exec/resume/--json을 지원하고 실제 환경에서 사용 가능할 때만**, 생성된 과제 폴더에서 다음 단일 세션 기록기를 사용할 수 있습니다.

```sh
node tools/worklog.cjs chat
```

요청을 여러 줄 입력한 뒤 `/send`를 입력하면 **원문 저장 → 현재 제공 Codex 실행 → 공개 메시지/도구 이벤트·종료 상태 저장** 순서로 진행합니다. 다음 요청은 같은 세션 ID로 이어가며 `/exit`로 끝냅니다. 기록기는 요청 ID와 판단 요약 작성 안내도 함께 전달합니다. 원문 파일과 실제 전달 입력은 별도로 보관하므로 안내가 덧붙었다는 사실을 확인할 수 있습니다.

모델을 자동 대체하거나 글로벌 계정·MCP·Codex 버전을 바꾸지 않습니다. 권한은 기본 CLI 설정을 따릅니다. 허용된 쓰기가 필요한 지원 환경에서는 `--workspace-write`를 명시할 수 있지만 관리 정책을 우회하지 않습니다. CLI 기능이 없거나 승인 입력이 필요하면 일반 제공 Codex와 AI 기록 방식으로 돌아갑니다. 하네스 밖 TUI·다른 세션·브라우저 입력은 수집하지 않습니다. reasoning 항목은 제외하며 설명 가능한 판단은 별도 note로 남깁니다.

기록기는 모델을 자동 대체하지 않습니다. **현재 제공 CLI에서 실제 응답이 확인된 허용 모델 ID**를 알고 있다면 `ask/chat --model 실제ID`로 그 실행에만 전달할 수 있습니다. 글로벌 모델/계정 설정은 바꾸지 않습니다. 모델 옵션을 생략하면 CLI 기본값을 사용하므로, 권장 모델만 사용하려는 경우 기본값이 다른 모델이면 그대로 진행하지 마세요. 표시명으로 ID를 추측하거나 오류를 다른 모델로 자동 우회하지 않습니다. `node tools/worklog.cjs --help`로 명령도 확인할 수 있습니다.

예상·실제 결과와 실행 명령을 같은 requestId로 연결하는 note/run 명령은 생성된 `docs/WORKFLOW.md`에 있습니다. 로그는 작업 공간 안에만 두고 공식 플랫폼 기록을 대체한다고 주장하지 않습니다. 기록기는 방화벽/격리 샌드박스가 아니며 시험 제한은 계속 적용됩니다.

## 과제 유형별로 고르는 방법

문제 이름이 아니라 입력·요구 결과로 고릅니다. 아래 예는 출제 예측이 아닙니다.

| 실제 상황 | 필요한 스킬·가이드 | 우선 확인할 결과 |
| --- | --- | --- |
| 무엇부터 할지 모르겠음 | task-triage → readme-to-requirements | 과제 위치·필수조건·제출물·미정 정책 |
| 기존 서비스 오류 수정 | debug-and-repair + implement-and-verify | 재현 입력 → 최소 수정 → 실패/성공 회귀 |
| CSV·JSON·로그 연결/분석 | data-to-validated-dataset + 설계·구현 | 행 의미·키·시간대·원본 대조·미매칭 |
| 매뉴얼 검색·FAQ·보고서 | document-to-evidence + 필요시 설계·구현 | 버전 정책·주장별 출처·답변 불가·충돌 |

```text

## 시험 작업 경계와 세션 운영

[자료 활용 경계](.agents/skills/task-triage/references/exam-boundary.md)와 [시험 지침 조각](templates/EXAM-GUARD.fragment.md)에 사용자 제공 운영 메일·가이드의 관련 내용을 정리했습니다. 최신 메일의 명시 안내가 기존 가이드와 다르면 메일을 우선하며, 안내하지 않은 부분은 가이드를 따릅니다. 아래는 준비용 정리이고 공식 안내를 대체하지 않습니다.

시험의 외부 전송·push·업데이트·Computer Use 금지와 도구 제한을 지켜 줘.
리뷰 중 코드를 바꾸지 말고 수정할 내용은 주작업에 인계해 줘.
```

실제 다중 세션이 허용되고 프런트/백엔드가 독립적일 때만 파일 소유권을 나눕니다. 공통 API·타입·루트 설정·잠금 파일·문서는 통합 담당 하나만 수정하고, 리뷰어는 동결한 상태를 읽기 전용으로 검토합니다. [세션 분담 가이드](.agents/skills/task-triage/references/session-plan.md)와 [인계 양식](templates/SESSION-HANDOFF.md)을 활용하세요. 병렬 실행이 반드시 빠르거나 시험에서 허용된다고 보장하지 않습니다.

### 하네스는 작게 시작

이 묶음의 기본 하네스는 **작업 지시 + 실제 실행/테스트 + 로컬 근거 + 인계/리뷰**입니다. 별도 모델 라우터·자동 다중 세션 런처·MCP·외부 로그 전송은 포함하지 않습니다. 지원 여부가 불명확한 CLI 옵션을 시험 환경에서 강제하지 않으며 버전/승인/샌드박스 설정도 임의로 바꾸지 않습니다. 실제 시험의 제공 CLI로 실행하고, 로컬 모의실험의 개인 로그인·모델·옵션을 그대로 가져가지 마세요.

그 결과 여러 파일 결합 가이드와 프롬프트에 **행 의미·차원 키 유일성, 날짜 추출 전 시간대 변환, 파서 성공과 계약 충족의 구분, 상충 키/제외 행 개수, 매칭/미매칭 수량 보존, 출력 보호와 재실행**을 보완했습니다. PDF/OCR·스프레드시트 추출·대규모 성능은 미검증입니다. 이 공개 저장소에는 범용 스킬·가이드와 자체 JS 연결 시작본을 두며 로컬 모의과제의 시작본·완성본·실행 로그나 실제 시험 자료는 포함하지 않습니다. 언어별 완성 답안이나 형식별 추출 실행기를 제공하는 묶음도 아닙니다.

JS 시작본은 Node 22.14.0에서 핵심 처리·오류·실제 CLI·HTTP/정적 파일을 포함한 4개 테스트가 통과했습니다. 서버는 실제 로컬 포트로 테스트했으며 자동 브라우저 검증은 포함하지 않았습니다. 시험장의 Node 버전과 화면 동작은 별도 확인이 필요합니다.

작업 공간·기록기는 자동 구조 생성·기존 파일 보존·원문 보존·명령 성공/실패·없는 실행 파일·미전송 초안을 실제로 확인했습니다. chat 입력 루프는 가짜 CLI로 검증했고, 공통 ask/resume 경로는 실제 로컬 Codex의 권장 5.6 Terra로 두 요청을 처리해 같은 세션 ID·원문 파일·응답·종료 0을 확인했습니다. 실제 시험 환경의 허용·지원 검증과는 별도입니다.

공개 저장소를 실제 clone한 뒤 별도 Codex CLI 세션에 CSV·JSON·로그 창작 과제를 맡기는 실험도 진행했습니다. 풀이 코드를 부모 대화가 직접 작성/수정하지 않고, 권장 5.6 Terra의 구현 세션과 별도 읽기 전용 리뷰를 사용했습니다. 기본 샘플 점검 후 큰 정수 정밀도 손실을 발견해 같은 구현 세션에 인계했고, 수정 후 7개 테스트와 11개 외부 점검이 통과했습니다. 원본·과제 안내는 보존됐습니다. 각 점검은 유한한 사례의 근거이며 모든 입력에 대한 증명이 아닙니다.
