# 처음 보는 과제의 작업 경로 고르기

특정 산업·언어·프레임워크·문제 유형을 예측하지 않는다. 실제 README·과제 안내·적용되는 AGENTS.md·파일 목록과 기존 실행 설정에서 작업 경로를 결정한다. 이 스킬 자체는 제품 구현이나 환경 변경을 허용하지 않는다.

## 첫 확인

대회·시험 준비물을 사용하는 경우 [자료 활용 경계](references/exam-boundary.md)를 읽고 실제 최신 안내와 대조한다. 시험 작업의 git push·외부 전송·Codex 업데이트 금지를 분명히 하고 공개 자료의 출처·적용 범위를 남긴다. 여러 세션이 필요하면 [세션 분담 가이드](references/session-plan.md)에 따라 실제 허용·지원 여부와 파일 소유권을 먼저 확인한다.

1. 실제 작업 폴더와 참고 스킬 폴더를 구분한다. 현재 파일과 사용자의 변경을 보존한다.
2. 사용자/입력/완료해야 하는 업무, 필수 제출물·실행 계약·금지 변경·도구 제한·남은 시간을 확인한다. 모르면 미확인으로 표시한다. 대용량 파일을 전부 읽기 전에 관련 경로부터 좁힌다.
3. 기존 코드 수정인지 새 기능인지, 데이터/문서/웹/API/제약 계산이 섞이는지 판단한다. 여러 유형일 수 있다. 파일 확장자나 공개 데모만 보고 과제 내용을 결정하지 않는다.
4. 실행 가능한 기존 명령과 의존성 상태, 핵심 미정 정책, 실패 위험을 파악한다. 실행하지 않은 명령은 확인 예정으로 적는다.

## 필요한 경로만 선택

다음 스킬이 같은 묶음에 있으면 필요한 것만 읽는다. 상대 경로는 이 스킬 폴더 기준이다. 설치 여부와 자동 인식에 의존하지 않고 파일 경로로 읽을 수 있다. 없으면 실제 자료를 바탕으로 같은 판단을 수행한다.

| 상황 | 경로 |
| --- | --- |
| 원문·완료 조건 정리 | [readme-to-requirements](../readme-to-requirements/SKILL.md) |
| CSV·JSON·로그·표의 탐색/가공 | [data-to-validated-dataset](../data-to-validated-dataset/SKILL.md) |
| 문서 검색·비교·근거 기반 답변 | [document-to-evidence](../document-to-evidence/SKILL.md) |
| 재현해야 하는 기존 오류 | [debug-and-repair](../debug-and-repair/SKILL.md) |
| 구성·입출력·알고리즘·검증 계획 | [requirements-to-design](../requirements-to-design/SKILL.md) |
| 구현과 실제 실행 | [implement-and-verify](../implement-and-verify/SKILL.md) |

## 짧은 작업 지도

터미널이 느리거나 파일 조작이 불편한 환경에서는 [작업 단위·파일 보존 가이드](references/terminal-workflow.md)를 적용한다. 공개 자료를 더 가져올 필요가 있을 때만 [선별 목록](references/public-sources.md)을 확인하며 일괄 설치하지 않는다.

기존 요구사항 문서나 응답에 목표, 필수 완료 조건, 필요한 경로, 첫 검증 입력, 막히는 질문, 다음 행동을 짧게 남긴다. 별도 관리 문서를 늘리지 않는다. 이미 분석·설계·구현까지 요청받았다면 필요한 확인 후 이어가고, 분석만 요청받았다면 작업 경로 제안에서 멈춘다.

시간이 알려졌다면 불확실성이 큰 부분을 작은 실행으로 먼저 확인하고, 끝까지 이어지는 최소 필수 흐름을 우선한다. 필수 조건을 시간 부족만으로 선택 사항으로 낮추지 않는다. 남은 시간이 짧으면 미완료 필수사항·실행 가능한 현재 상태·검증 근거·제출 안내를 명확히 한다. 문서나 선택 기능을 늘리느라 필수 동작 검증을 밀지 않는다.
