# AI Native Workflow Skills

README 기반 과제를 파악하고, 요구사항·데이터·설계·코드·검증 근거를 연결하기 위한 한국어 Codex 스킬 묶음입니다. 특정 언어·프레임워크·MCP·외부 모델을 필수로 사용하지 않습니다.

**바로 사용하기:** [clone 명령](#1-응시-화면-안에서-가져오기) → [단계별 복사 프롬프트](#2-단계별-복사-프롬프트-설치-없이-사용).

**문제가 낯설다면:** [처음 시작할 프롬프트](#처음-보는-과제에서-시작하기) → [유형별 선택표](#과제-유형별로-고르는-방법) → [추가 상황별 복사 프롬프트](#상황별-추가-복사-프롬프트).

데이터가 있는 과제는 **단계 1 → 데이터 탐색 → 단계 2·3 → 단계 4에서 데이터 가공 → 단계 5 대조·검증** 순서로 적용합니다. [현재 준비 상태](#현재-준비-상태)도 확인할 수 있습니다.

## 포함된 스킬

| 순서 | 스킬 | 용도 | 기본 산출물 |
| --- | --- | --- | --- |
| 선택 0 | `task-triage` | 처음 받은 과제의 목표·환경·유형·위험을 확인하고 필요한 경로 선택 | 응답 또는 기존 문서의 짧은 작업 지도 |
| 1 | `readme-to-requirements` | README·관련 자료 분석, 필수 조건·출처·완료 기준·가정·질문 정리 | `docs/requirements.md` |
| 데이터가 있을 때 | `data-to-validated-dataset` | 자료 탐색·추출·정규화·중복/충돌 처리·결합·집계·원본 대조 | 기존 문서의 데이터 절, 필요시 `docs/data-notes.md`; 가공 요청 시 코드·데이터·검증 근거 |
| 문서가 핵심일 때 | `document-to-evidence` | 버전·충돌·출처를 구분한 검색·근거 기반 답변·인수인계 요약 | 과제의 문서/검색 결과와 검증 근거 |
| 기존 오류가 있을 때 | `debug-and-repair` | 기준 실행·재현·가설 확인·최소 수정·회귀 검증 | 기존 코드의 수정과 재현/회귀 근거 |
| 2 | `requirements-to-design` | 최소 설계, 필요한 Mermaid 다이어그램, 자료구조·알고리즘 선택, 검증 계획·구현 순서 | `docs/design.md` |
| 3 | `implement-and-verify` | 프로젝트 컨벤션에 맞춘 구현, 실제 실행·검증, 설명 근거와 한계 기록 | 코드와 `docs/verification.md` |

기존 문서와 제출 양식이 있으면 해당 위치·형식을 우선합니다. 분석만 요청했으면 구현까지 진행하지 않고, 구현까지 요청했다면 불필요한 승인 대기 없이 요청 범위에서 이어갑니다.

**총 7개 스킬이며 전부 실행하는 순서표가 아닙니다.** 요구사항·설계·구현 흐름을 기본으로, 해당 과제에 필요한 데이터·문서·오류 진단만 추가합니다. 상세 가이드도 필요한 항목만 읽습니다.

## 처음 보는 과제에서 시작하기

아래 프롬프트는 clone 후 실제 과제 폴더의 Codex에서 사용합니다. 먼저 과제를 분류하고 작업 계획만 확인하고 싶을 때 적합합니다.

```text
/home/user/exam-kit/.agents/skills/task-triage/SKILL.md를 읽고 적용해 줘.
실제 과제 폴더, 적용되는 AGENTS.md, README·제출 안내·파일 목록·실행 설정을 확인해 줘.
문제 분야나 기술 스택은 미리 가정하지 마.
목표·필수 완료 조건·수정 금지 영역·제출 파일·도구 제한을 출처와 함께 정리하고,
기존 코드 수정/새 기능/데이터/문서/웹/API/제약 계산 중 필요한 작업 경로를 골라 줘.
필요한 스킬과 참조 가이드만 선택하고, 첫 검증 입력과 막히는 질문도 알려줘.
이번에는 분석과 계획까지만 하고 제품 코드·원본 데이터·환경 설정은 수정하지 마.
```

계획을 확인한 뒤 아래 단계별 프롬프트를 사용합니다. 처음부터 구현까지 맡기고 직접 결과를 확인할 계획이라면 다음 블록을 쓸 수 있습니다.

```text
/home/user/exam-kit/.agents/skills/task-triage/SKILL.md를 읽고 적용해 줘.
과제 README와 실제 프로젝트를 기준으로 요구사항 확인부터 설계·구현·검증까지 진행해 줘.
참고 스킬 폴더와 실제 과제 폴더를 구분하고 기존 파일·계약·내 변경을 보존해 줘.
필요한 스킬과 가이드만 읽어 적용하고, 전부 사용하기 위해 범위를 늘리지 마.
데이터/문서/기존 오류가 있으면 해당 절차를 선택해서 원본·출처·실행 근거를 연결해 줘.
컨벤션과 기존 명령을 먼저 확인하고 작은 필수 흐름부터 구현해 줘.
확정·가정·미정을 구분하고 진행을 막는 정보가 없을 때만 질문해 줘.
관련 정상·실패·경계 사례를 실제 검증하고 미실행·미완료를 정확히 남겨 줘.
시험의 실제 도구 제한을 따르고 금지된 Computer Use·외부 모델 연결은 사용하지 마.
새 MCP·외부 서비스·배포를 임의로 추가하지 마.
과제 산출물과 재현 방법은 실제 제출 위치에 남기고 최종 제출 확정은 내가 직접 할게.
```

## 과제 유형별로 고르는 방법

문제 이름이 아니라 입력·요구 결과로 고릅니다. 아래 예는 출제 예측이 아닙니다.

| 실제 상황 | 필요한 스킬·가이드 | 우선 확인할 결과 |
| --- | --- | --- |
| 무엇부터 할지 모르겠음 | task-triage → readme-to-requirements | 과제 위치·필수조건·제출물·미정 정책 |
| 기존 서비스 오류 수정 | debug-and-repair + implement-and-verify | 재현 입력 → 최소 수정 → 실패/성공 회귀 |
| CSV·JSON·로그 연결/분석 | data-to-validated-dataset + 설계·구현 | 행 의미·키·시간대·원본 대조·미매칭 |
| 매뉴얼 검색·FAQ·보고서 | document-to-evidence + 필요시 설계·구현 | 버전 정책·주장별 출처·답변 불가·충돌 |
| API·저장·중복/재시도 | 설계·구현 + [API 가이드](.agents/skills/implement-and-verify/references/api-and-state.md) | 계약·실제 저장·실패/재시도·관련 동시성 |
| 작은 웹 도구·대시보드 | 설계·구현 + [웹 흐름 가이드](.agents/skills/implement-and-verify/references/web-flow.md) | 입력→결과→저장/내보내기와 오류 표시 |
| 알람 사건화·우선순위 | 데이터 + [알고리즘](.agents/skills/requirements-to-design/references/algorithm-choice.md)·[제약 가이드](.agents/skills/requirements-to-design/references/constraints-and-ranking.md) | 그룹 경계·동률·업무 규칙·원본 추적 |
| 일정·자원·비용 계획 | 설계·구현 + 제약 가이드 | 실행 가능성·기준안·목표값·최적성 한계 |
| 테스트가 없거나 불충분 | [검증 선택 가이드](.agents/skills/implement-and-verify/references/test-selection.md) | 원문 기반 독립 기대값·핵심 실패 사례 |
| 처음 보는 언어·컨벤션 | 구현 스킬의 conventions·language-recipes | 실제 버전·기존 규칙·작은 문법 확인 |

문서 제출 과제라면 코드·웹앱이 필요하다고 추론하지 않습니다. 웹/API 과제라도 외부 AI API가 제공된다고 가정하지 않습니다. 원문 필수조건을 확인한 뒤 관련 경로만 적용합니다.

## 시험 환경에서 clone해서 사용하기

시험 내 스킬 반입·공개 자료 사용이 허용되는지 먼저 확인하세요. 공개 개인 MCP 설정 반입 허용이 범용 스킬 묶음 전체의 반입 허용을 자동으로 의미하지는 않습니다. 실제 응시 안내와 제공 도구 제한을 따릅니다.

### 1. 응시 화면 안에서 가져오기

개인 PC 파일 업로드 대신, 허용된 경우 **응시 환경의 터미널과 제공 AI**로 가져옵니다.

```sh
git clone --depth 1 -- https://github.com/imjanghyeok/ai-native-workflow-skills.git /home/user/exam-kit
git -C /home/user/exam-kit rev-parse HEAD
ls -a /home/user/exam-kit/.agents/skills
```

`/home/user/exam-kit`은 가져온 스킬을 두는 예시 위치이며 과제 폴더와 구분합니다. 이미 그 폴더가 있다면 내용을 확인하고 다른 빈 경로를 사용하세요. 기존 과제·설정·파일을 삭제하거나 덮어쓰지 않습니다. 가져온 커밋 ID를 남겨 어떤 준비물을 사용했는지 확인할 수 있게 합니다.

제공 AI에게 요청할 예:

```text
공개 저장소 https://github.com/imjanghyeok/ai-native-workflow-skills.git 를
/home/user/exam-kit 에 clone해 줘. 폴더가 이미 있으면 덮어쓰지 말고 상태를 알려줘.
가져온 README와 스킬 목록을 확인하고 커밋 ID를 알려줘.
과제 파일·AGENTS.md·Codex 설정 전체는 변경하지 마.
```

### 2. 단계별 복사 프롬프트 (설치 없이 사용)

clone을 마친 뒤 **실제 과제 폴더에서** 제공 Codex를 실행합니다. 터미널에서 실행하는 환경이라면 명령은 `codex`입니다. 이미 Codex가 실행 중이면 그 대화에서 이어가세요.

아래 코드 블록을 **한 단계씩 복사**하고, 결과를 읽은 뒤 다음 단계로 진행하세요. `/home/user/exam-kit`을 다른 위치로 바꿨다면 프롬프트의 경로도 바꿉니다. 자동 스킬 설치나 MCP 연결 없이, 스킬 파일을 읽어 절차를 적용하는 방식입니다. 상대 경로로 연결한 `references/` 문서는 해당 스킬 폴더를 기준으로 읽습니다.

#### 단계 1 · README와 현재 프로젝트 분석

```text
/home/user/exam-kit/.agents/skills/readme-to-requirements/SKILL.md를 읽고 적용해 줘.
먼저 현재 작업 경로와 실제 과제 폴더를 확인해 줘.
/home/user/exam-kit은 참고 스킬 폴더이며 과제 폴더와 구분해 줘.
과제 폴더를 확정할 근거가 없으면 경로를 추측하지 말고 나에게 확인해 줘.

적용되는 AGENTS.md, 과제 README·안내, 기존 코드·데이터·테스트·실행 설정을 읽어 줘.
다음 내용을 출처 파일·위치와 함께 정리해 줘.
1. 해결할 문제와 사용자가 끝낼 수 있어야 하는 업무
2. 필수 기능·제약·제출 파일·실행 방법
3. 현재 구현된 부분과 부족한 부분
4. 확인된 사실, 가정, 모호하거나 충돌하는 사항

제공 자료의 예시를 이번 과제의 필수 요구사항으로 단정하지 마.
이번 단계는 분석만 하고 제품 코드는 수정하지 마.
```

#### 데이터가 있는 경우 · 단계 1 뒤에 탐색만 수행

CSV·JSON·로그·스프레드시트·PDF 등 제공 자료가 업무 입력일 때만 적용합니다. 이 요청은 구조와 품질을 조사하는 단계이며 가공 실행 단계와 구분합니다.

```text
/home/user/exam-kit/.agents/skills/data-to-validated-dataset/SKILL.md를 읽고 적용해 줘.
이번에는 데이터 탐색과 규칙 정리만 해 줘. 원본을 바꾸거나 가공 코드를 구현하지 마.
가공 결과 파일 생성·패키지 설치·설정 변경도 아직 하지 마.

과제에 필요한 제공 자료부터 파일·시트·형식·규모와 작은 표본을 확인해 줘.
한 행/항목의 의미, 필드·타입·단위·날짜/시간대·키 후보와 출처 위치를 정리해 줘.
원본값과 정규화값, ID 선행 0, 0/null/빈 값, 비율과 퍼센트를 구분해 줘.
중복·상충 ID·잘못된 값·누락·파싱 실패 가능성을 확인하고,
여러 자료를 연결한다면 키 관계·미매칭·행 증식 위험을 짚어 줘.
자료마다 한 행의 의미와 차원 키 유일성을 확인하고,
날짜 결합 전에 적용할 시간대와 파서의 엄격성도 확인해 줘.
표본으로 본 것과 전체를 실제 검사한 결과를 구분하고 수치를 추측하지 마.

필요한 추출·정제·결합·집계 규칙과 원본 대조 계획을
확정·가정·미정으로 나누고, 판단에 필요한 업무 질문을 초안으로 남겨 줘.
도구가 없어 읽지 못한 형식이나 범위도 표시해 줘.
기존 요구사항 문서에 데이터 절로 정리하고,
별도 문서가 필요할 만큼 크면 실제 과제 폴더의 docs/data-notes.md에 정리해 줘.
```

#### 단계 2 · 요구사항과 완료 기준 정리

```text
앞서 읽은 원본 README와 관련 자료를 바탕으로 요구사항을 정리해 줘.
각 요구사항에 R-01 같은 ID를 붙이고 다음을 연결해 줘.
- 요구사항과 출처
- 필수·권장·선택 여부: 원문에 없는 우선순위는 제안이라고 표시
- 확정·가정·미확인 상태
- 관찰하거나 실행해서 확인할 수 있는 완료 기준
- 검증할 정상·실패·경계 사례

데이터 탐색 결과가 있으면 입력 단위·키·타입·단위·변환 규칙·대조 기준도 연결해 줘.

업무 배경·업무 규칙 질문은 현업 담당자용으로,
플랫폼 사용·응시 절차 질문은 Helper용으로 구분해 초안을 작성해 줘.
질문을 실제로 보냈거나 답변을 받았다고 기록하지 마.
```
