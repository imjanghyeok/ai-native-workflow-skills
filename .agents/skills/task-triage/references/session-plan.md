# 세션 분담과 가벼운 하네스

## 기본값: 한 구현자 → 변경 동결 → 리뷰

한 Codex가 요구·계약·구현·검증을 작은 업무 단위로 진행한다. 단위가 끝나면 입력/기대값·변경 파일·실제 결과·미확인 범위를 인계한다. 그 상태를 바꾸지 않는 리뷰 단계에서 원문과 코드·실행 근거를 대조한 뒤, 지적을 다시 구현 단계로 돌린다. 새 세션을 만들 수 없으면 같은 대화에서 역할을 바꿔 수행하되 독립 리뷰라고 부르지 않는다.

작은 CLI·데이터 처리 과제에 프런트/백엔드 3세션을 미리 만들지 않는다. 설치·정리·인계 비용과 CPU/RAM 사용이 실제 병렬 이득보다 클 수 있다. 모델 응답 대기와 리소스도 시간 예산에 포함한다. 병렬이면 반드시 빨라진다고 주장하지 않는다.

## 동시 세션이 실제 허용·지원될 때만

한 주작업 세션 + 제한된 읽기 전용 검토/자료 분석 세션부터 검토한다. 필요한 프런트·백엔드가 독립된 경우에만 나눈다.

| 역할 | 책임·경계 |
| --- | --- |
| 주작업/통합 | README·요구사항·공통 API 계약, 루트 설정·의존성·통합 테스트·최종 점검 |
| 프런트 담당 (필요할 때) | 합의한 입력·응답·오류 계약으로 지정 UI 파일만 수정. 서버 계약·공통 설정 임의 변경 금지 |
| 백엔드 담당 (필요할 때) | 지정 처리/API 파일만 수정. UI·공통 계약·루트 의존성 임의 변경 금지 |
| 리뷰어 | 동결한 코드·계약·원본·실제 결과 대조. 소유 파일을 수정하지 않고 발견·근거·영향·재현 방법 전달 |

작업 분리는 역할 이름보다 **소유 파일·읽기/쓰기 범위·입출력 계약·완료 기준**으로 한다. package/잠금 파일·공통 타입·데이터 원본·공통 문서는 통합 담당만 바꾼다. 같은 파일을 에디터와 AI 또는 여러 세션이 동시에 수정하지 않는다. 리뷰 중 파일이 바뀌면 검토한 상태와 현재 상태를 구분해 관련 검증만 갱신한다.

## ‘하네스’의 최소 구성

하네스는 작업 지시·실행 결과·검증·인계를 연결하는 장치다. 별도 모델이나 다중 세션을 필수로 만들 필요가 없다. 첫 구현은 고정 프롬프트, 로컬 실행 로그, 실제 검증 명령, 인계 표로 충분할 수 있다. 대회 CLI에 없는 옵션·API·서브에이전트 기능을 있다고 가정하지 않는다.

기존 테스트 실행기로 독립 기대값을 검사하고, 결과를 스크립트/문서로 연결한다. 자동화가 필요할 때만 현재 CLI의 도움말로 지원 옵션을 확인한다. 제공 버전·관리 설정·승인/샌드박스·감독 프로세스를 바꾸지 않으며 자동 승인 우회 옵션을 안내하지 않는다. 실패한 단계를 성공으로 넘기거나 무제한 재시도하는 자동 루프를 만들지 않는다.

추가 세션이 차단되거나 느리면 새 계정/접속 경로로 우회하지 않고 단일 흐름으로 돌아간다. 로컬 모의실험에서 다중 세션을 실행해도 시험 환경의 허용·성능 검증과는 별도다.
